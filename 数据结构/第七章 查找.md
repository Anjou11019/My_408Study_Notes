# 考点1 线性表的查找

##### 9.1

选择题考频：6/16年
大题考频：1/16年

## 顺序查找

**知识点**：
1. 顺序查找可以用于顺序/链式存储，且**不要求**元素有序
2. 算法简单，但ASL较大，查找效率不高
3. 当查找表规模较大时，不适合使用顺序查找

**ASL分析**：
$$
ASL_{成功} = \dfrac{1+2+3+...+n}{n}=\dfrac{n+1}{2}
$$
$$
ASL_{失败} = n+1(有哨兵)、n(无哨兵)、\dfrac{n}{2}+\dfrac{n}{n+1}(有序优化)
$$
*有序优化的失败ASL分析使用用到查找判断树更方便分析*

## 折半查找

**知识点**：
1. 折半查找只适用于**顺序存储**（需要随机访问的特性快速定位），且要求元素必须**有序**
2. mid选取必须保证整体一致，即默认左右选左（**向下取整**）
3. 折半查找可将时间复杂度优化到$O(\log_2n)$，查找效率较高
4. 折半查找的最多比较次数 = 折半查找判定树的树高 = 相同节点数量的完全二叉树的高度 = $\lceil \log_2(n+1)\rceil$

**ASL分析**
$$
ASL_{成功}=\dfrac{关键字查找成功比较次数之和}{查找元素个数}
$$
$$
ASL_{失败}=\dfrac{关键字查找失败比较次数之和}{不成功位置个数}
$$

## 分块查找

**知识点**：（可以理解为顺序的索引查找）
 1. 索引表中的每个元素含有各块的最大关键字和各块中第一个元素的地址
 2. ==块内元素无序，但块间必须有序==
 3. 索引表是**有序表**，可使用**顺序/折半查找**
    但是块内是**无序的**，只能使用**顺序查找**
 4. 如果既要保证查找效率，又要满足表中元素动态变化的需求，首选分块查找

**ASL分析**：（索引表有**b**个块，每个块内含有**s**个记录）
$$
折半+顺序:ASL_{成功} = \dfrac{关键字查找成功比较次数}{查找元素个数}+\dfrac{s+1}{2}
$$
$$
顺序+顺序:ASL_{成功}=\dfrac{b+1}{2}+\dfrac{s+1}{2}
$$

BSTNode* BST_Search(BSTree T,int key){
	while(T!=nullptr&&key!=T->data){
	//若树空或等于根节点值直接结束
		if(key<T->data){
			T->lchild;//若key<节点值，从左子树找

bool BST_Insert(BSTree T,int key){

	else if(k == T->data)

	else return BST_Insert(T->rchild,k);

##### 9.2

平衡二叉树AVL：满足任一节点左右子树高度差不超过1的二叉排序树BST
## 查找

规则和BST完全一致

## 插入

离插入节点**最近**且**平衡因子绝对值超过1**的祖先节点，以该节点为根的子树称为**最小不平衡子树**，插入后导致AVL不平衡，则调整范围就是最小不平衡子树

| 操作  | 过程                                                 |
| --- | -------------------------------------------------- |
| 左旋  | 1.右子节点变为旋转节点的父节点<br>2.右子节点的**左子节点**变为旋转节点的**右子节点** |
| 右旋  | 1.左子节点变为旋转节点的父节点<br>2.左子节点的**右子节点**变为旋转节点的**左子节点** |

**插入及调整操作**：

| 类型                   | 操作                                |
| -------------------- | --------------------------------- |
| LL（最小不平衡节点在其左子树的左子树） | **右旋**不平衡节点                       |
| RR                   | **左旋**不平衡节点                       |
| LR                   | 先**左旋**不平衡节点的**左孩子**，再**右旋**不平衡节点 |
| RL                   | 先**右旋**不平衡节点的**右孩子**，再**左旋**不平衡节点 |

## 删除

| 情况                       | 操作                                     |
| ------------------------ | -------------------------------------- |
| 删除叶子节点                   | - 删除后依旧平衡则直接删除<br>- 删除后不平衡，则转换为插入情况并调整 |
| 删除节点有左/右孩子               | 删除后左/右孩子上位，转换为插入情况并调整                  |
| 删除节点有左右孩子且删除节点的**左子树**更深 | 交换删除结点和**中序前驱**，转换为插入情况并调整             |
| 删除节点有左右孩子且删除节点的**右子树**更深 | 交换删除节点和**中序后继**，转换为插入情况并调整             |

## 性质

高度表

|       |     |     |     |     |     |     |     |     |
| ----- | --- | --- | --- | --- | --- | --- | --- | --- |
| h     | 1   | 2   | 3   | 4   | 5   | 6   | 7   | 8   |
| $n_h$ | 1   | 2   | 4   | 7   | 12  | 20  | 33  | 54  |

**性质**：
 1. 假设$n_h$表示深度为h的平衡二叉树中含有的最少节点数，则$n_h =n_{h-2}+n_{h-1}+1$（此时非叶节点的平衡因子为1或-1）
 2. n个节点的AVL**最小高度**为$\lceil \log_2(n+1)\rceil$
 3. 若AVL的高度为h，则树中最多有$2^h-1$个节点

**做题结论**：
 - 若将一个有序序列按序插入平衡二叉树，且总数满足$2^n-1$，则AVL树一定是个满二叉树

# 考点4 B树和B+树

## 结点结构

| n                 | $p_0$                      | $k_1$ | $p_1$                 | $k_2$ | $p_3$ | ... |
| ----------------- | -------------------------- | ----- | --------------------- | ----- | ----- | --- |
| n为结点内关键字的个数（一般省略） | $p_0$所指子树的所有结点的关键字均小于$k_1$ | 关键字   | $p_1$所指子树的关键字均大于$k_1$ |       |       |     |

## 性质

|                | B树                                                                     | B+树                                                    |
| -------------- | ---------------------------------------------------------------------- | ------------------------------------------------------ |
| 关键字和子树关系       | n个关键字对应n+1棵子树                                                          | n个关键字对应n棵子树                                            |
| 根节点子树          | $[2,m]$                                                                | $[2,m]$                                                |
| 根节点关键字         | $[1,m-1]$                                                              | $[2,m]$                                                |
| 非根节点子树         | $[\lceil\frac{m}{2}\rceil,m]$                                          | $[\lceil\frac{m}{2}\rceil,m]$                          |
| 非根节点关键字        | $[\lceil\frac{m}{2}\rceil-1,m-1]$                                      | $[\lceil\frac{m}{2}\rceil,m]$                          |
| 叶子节点/失败节点/终端节点 | 所有叶子节点在同一层且不携带信息（类比折半查找判定树的失败节点）                                       | 叶子节点包含了所有关键字信息以及指向含这些关键字记录的指针<br>叶子节点本身按照关键字大小从小到大顺序链接 |
| 操作方式           | 随机查找                                                                   | 随机查找和顺序查找                                              |
| 高度             | $\log_m(n+1)\leq h\leq\log_{\lceil\frac{m}{2}\rceil}(\frac{n+1}{2})+1$ |                                                        |

## 查找

B树的查找与二叉排序树类似，只不过每个节点包含多个关键字

B树中大多数操作所需的**磁盘存取次数与树的高度成正比**
![[B树.png]]
B树由于节点内存放关键字，所以导致查找效率较低
 - 因为需要将不需要的数据读入磁盘分析


![[B+树.png]]
B+树解决了此问题，非叶节点指存放索引，
 - 对于B+树，查找必须找到叶子节点才能停，因为非叶节点中存放的只是**索引**
 - 由于有一个头指针指向第一个叶子节点，因此可以通过叶子节点直接的指针实现数据的**顺序查找**
## 插入

| 插入后节点关键字个数 ≤ m-1 | 直接插入                                                        |
| 插入后节点关键字个数 > m-1 | 节点（插入后的）第$\lceil\dfrac{m}{2}\rceil$个关键字进入父节点<br>源节点**一分为二** |

**B+树**

| 情况             | 操作                                                |
| -------------- | ------------------------------------------------- |
| 插入后节点关键字个数 ≤ m | 直接插入                                              |

## 删除

*为了方便论述，研究删除所讨论的终端节点指的是最下排的一层含关键字的节点，而不是不含任何信息的叶子节点/外部节点*

**B树**：
 1. 被删关键字不在终端节点
     - 用被删关键字的**前驱/后继**关键字代替被删关键字的位置，转化为删除终端节点关键字的情况
 2. 被删关键字在终端节点
     1. 删除后关键字个数$\geq \lceil\dfrac{m}{2}\rceil-1$
         - 直接删
     2. 删除后关键字个数$<\lceil\dfrac{m}{2}\rceil-1$，且兄弟**够借**
         - 父下子上
     3. 删除后关键字个数$<\lceil\dfrac{m}{2}\rceil-1$，且兄弟**不够借**
         - 父下与子合并

**B+树**（只在终端节点才会触发）
 - 被删关键字在终端节点
    1. 删除后关键字个数 $\geq \lceil\dfrac{m}{2}\rceil$
        - 直接删
    2. 删除后关键字个数 < $\lceil\dfrac{m}{2}\rceil$ 且兄弟**够借**
        - 兄弟节点的关键字进入当前节点
    3. 删除后关键字个数 < $\lceil\dfrac{m}{2}\rceil$ 且兄弟**不够借**
        - 当前节点与兄弟节点合并
 - ==**删除过程中需要时刻保持终端节点关键字和非终端节点关键字的一致性**==

# 考点5 散列Hash表

# 术语

| 名词          | 解释                                                  |
| ----------- | --------------------------------------------------- |
| 同义词         | 具有**相同**散列函数值的关键字                                   |
| 非同义词        | 具有**不同**散列函数值的关键字                                   |
| 冲突/碰撞       | 不同的关键字映射到了同一散列地址的现象                                 |
| ==堆积/二次聚集== | 用线性探测法处理同义词冲突过程中又添加了非同义词的冲突                         |
| 装填因子        | 装填因子$\alpha = \dfrac{n}{m} =\dfrac{表中关键字个数}{散列表长度}$ |

**构造散列函数的方法**（易混知识点）
 - 直接定址法
 - 除留余数法
 - 数字分析法
 - 平方取中法

**处理冲突的方法**（易混知识点）
 - 开放定址法：$H_i=(H(key)+d_i)\%m,d_i为第i次探测的增量$
    - 线性探测法
        - 如果地址被占用，就接着往后一个一个找，找到第一个空位放入即可（会引发堆积/二次聚集）
    - 平方探测法（$d_i=1^2,-1^2,2^2,-2^2...$）
        - 无法探测所有空间，只能探测一半
    - 双散列法（$d_i=iH_2(key)$）
        - 当第一个散列函数发生冲突时，利用第二个散列函数计算地址增量
        - $H_i=(H(key)+iH_2(key))\%m$
    - 伪随机序列法
        - 增量序列由一个伪随机生成器产生 
 - 链地址法

## 处理冲突的方法

### 线性探测法

**知识点**：
  1. 冲突发生时，顺序查看表中下一单元，直到找出一个空闲单元或查遍全表
  2. 探测到表尾时，下一个探测地址是表头
  3. 处理同义词的冲突过程可能又添加了非同义词的冲突
  4. 不可以直接删除散列表中关键字，仅做**删除标记**

### 平方探测法

**知识点**：
 1. $H_i=(H(key)+d_i)\%m$（$d_i=1^2,-1^2,2^2,-2^2...$）
 2. 散列表长度m必须是一个可以表示成4k+3的素数
 3. 可以避免堆积，但无法探测到散列表上的所有单元
 4. 不可以直接删除散列表中的关键字，仅做删除标记

### 链地址法

**知识点**：
 1. 将所有的同义词存储在一个链表中，这个链表由其散列地址唯一标识
 2. **可以**直接==删除关键字==

## 散列表影响查找效率的因素

**知识点**：
 1. 装填因子$\alpha$
     1. $\alpha = \dfrac{n}{m} =\dfrac{表中关键字个数}{散列表长度}$
     2. $\alpha$ 定义了一个散列表的装满程度，$\alpha$越大，产生冲突的可能性越大
     3. ==平均查找长度ASL与n或m**无直接关系**，而是依赖于**装填因子**==$\alpha$
		   - **拉链法查找成功**时，ASL ≈ $1 + \dfrac{\alpha}{2}$
		   - **线性探测法查找成功**时，ASL ≈ $\dfrac{1}{2}(1 + \dfrac{1}{1-\alpha})$
		   - 不同冲突处理方法对应的ASL公式不同，不能混用，做题时注意区分“成功/失败”和“处理方法”。
 2. 散列函数：散列函数设计的越好，关键字分布**越均匀**，产生冲突的可能性**越小**，查找路径**越短**
 3. 处理冲突的方法：决定了发生冲突后查找的效率，有些方法可能还会引入新的冲突，造成查找距离变长

# 考点6 红黑树

## 定义与性质

**知识点**：
 1. 结点是<span style="color:red;font-weight:bold;">红色</span>或者**黑色**，根节点和叶子节点必是**黑色**
 2. 每个<span style="color:red;font-weight:bold;">红节点</span>必须有两个**黑色的**子节点，即不能出现两个连续的<span style="color:red;font-weight:bold;">红节点</span>
 3. 从任一节点到每个叶子节点的所有路径都包含相同数目的**黑色节点**
 4. 从某节点出发（不含该节点）到达任一叶子节点（包含叶子节点）的路径上的**黑节点**总数即为**黑高bh**

**性质**：
 1. 根节点的**黑高** $\geq\dfrac{h}{2}$
 2. 从根节点到叶节点的最长路径 $\leq$ 最短路径的2倍
     - 最短路径上只有**黑节点**
     - 最长路径中<span style="color:red;font-weight:bold;">红节点</span>的个数 = 黑节点的个数，交替出现
 3. 有n个内部节点的红黑树的高度$h\leq2\log_2(n+1)$

![[红黑树示例图1.png]]

**思考**：根节点黑高为h的红黑树，内部节点数**至少**有多少个？
 - 内部节点最少的情况 -- 总共h层黑节点的满树情况
 - ==若根节点黑高为h，内部节点数至少有==$2^h-1$个
**推论**：如果红黑树总高度=h，则黑高bh ≥ $\dfrac{h}{2}$，因此内部节点数$n \geq 2^{\frac{h}{2}}-1$，从而得出$h\leq2\log_2(n+1)$

## 插入

**规则**：
 1. 插入的节点一定为<span style="color:red;font-weight:bold;">红节点</span>
 2. 染色就是红黑互换

**插入操作**：
 1. 空树
     - 直接插入，**染色**
 2. 父**黑**
     - 直接插入
 3. <span style="color:red;font-weight:bold;">父红</span>且<span style="color:red;font-weight:bold;">叔红</span>
     - 叔父染色，祖父染色
     - 若祖父是根节点，祖父染色，否则不变
 4. <span style="color:red;font-weight:bold;">父红</span>且**叔黑**
     1. LL
         - 祖父<span style="color:red;font-weight:bold;">右旋</span>，父亲、祖父染色
     2. LR
         - 父亲<span style="color:red;font-weight:bold;">左旋</span>，父亲看作新节点，重新判断类型并调整
         - 或者和AVL一样左、右旋转，儿换爷+染色
     3. RR
         - 祖父<span style="color:red;font-weight:bold;">左旋</span>，父亲、祖父染色
     4. RL
         - 父亲<span style="color:red;font-weight:bold;">右旋</span>，父亲看作新节点，重新判断类型
         - 或者和AVL一样右、左旋转，儿换爷+染色

## 红黑树 v.s. AVL

**知识点**：
 1. 设计红黑树的目的是解决AVL维护起来比较麻烦的问题，红黑树的读取略逊于AVL，维护强于AVL，每次插入和删除的平均旋转次数远小于AVL
 2. AVL追求**严格平衡**，必须满足左右子树高度相差不超过1，而红黑树放弃追求完全平衡，它的旋转次数少，**插入最多2次旋转，删除最多3次旋转**，所以对于搜索、插入、删除操作较多的情况下，红黑树的效率是优于AVL的
 3. 红黑树和AVL插入删除、删除的**时间复杂度**均为$O(\log_2 n)$

# 整数的表示与类型转换

##### 9.17

## n bit整数表示范围

**范围**：
 - 无符号整数：$0\sim 2^n-1$
 - 带符号整数（补码）：$-2^{n-1}\sim 2^{n-1}-1$（==负数多一个==）

*手算的原理：先手算求数学真值，再检查是否超出相对应类型的表示范围*
 - **带符号整数**：
    - 溢出 OF=1
       - $C_n\oplus C_{n-1}$
    - SF：正数&零=0 / 负数=1
    - ZF：如果是零=1
    - CF：==不能使用手算的方式逆推==
 - **无符号整数**：
    - SF：没有意义
    - CF：溢出=1
       - $C_{out}\oplus C_{in}=C_n\oplus C_0$
    - ZF：如果是零=1
    - OF：不能猜
## 补码快速转原码

**补码转原码**：
 1. 符号位为0：补码与原码相同，直接解释真值
 2. 符号位为1：从右到左找到第一个1，==该位及其**右边**保持不变==，它左边的所有数值位取反，符号位保持为1
 - **特别的**：补码$10...0$表示$-2^{n-1}$，无法转换成同位宽原码，直接写真值

## <span style="color:red;font-weight:bold">不同类型整数变量之间转化，位宽和类型变化</span>

一句话总结：==先按照“原有符号性”完成拓展/截断，再按照“目的符号性”解释==
 - 同宽转换：位串不变，只改变解释方式
 - 位宽变大
    - **原数是带符号数**：先符号扩展（复制符号位），再按目的类型解释
    - **原数是无符号数**：先零拓展（高位补0），再按目的类型解释
 - 位宽变小：截断，只保留低位，再按目的类型解释

### 练习1（几乎包含全情况）

*考研一般情况`short unsigned short`为16位，`int unsigned int`为32位*
```cpp

short a =-122;
//FF86H 有符号拓展-> FFFF FF86H 按目的有符号数解释为-122
int b = a //带符号->带符号

// 0xFF86 零拓展-> 0000 FF86H 按无符号目的数解释为65414

// II  位宽变小（32-16）、类型不变
int g = 0x00018009;
//0x00018009 截断-> 8009H 按有符号解释为 -32759
short h = g; // 带符号 -> 带符号

// III 位宽不变（16-16）、类型变化（带符号/无符号互转） 
short e = -1;
//FFFFH -> 直接按无符号数解读为 65535
unsigned short f = e;//带符号 -> 无符号

// IV  位宽变大（16-32）、类型也变（带符号/无符号互转）
ungigned short p = 0xFF86;
//FF86H 零扩展-> 0000 FF86H 按带符号数解释为65414
int p = q; //无符号->带符号

short r = -1;
//FFFFH 带符号扩展-> FFFF FFFFH 按照无符号数解释为2^{32} - 1
unsigned int s = r; // 带符号->无符号

// V   位宽变小（32-16）、类型也变（带符号/无符号互转）
int t = -1;
//FFFF FFFFH 截断保留-> FFFFH 按照无符号数解读为65535
unsigned short u = t;//带符号 -> 无符号

unsigned int t2 = 65535;
// 0000 FFFFH 截断保留-> FFFFH 按照带符号数解读为-1
short u2 = t2;      //无符号 -> 带符号（截断保留）
```

| ----- | ---------------- | --------------- |
| C语言层  | 赋值、强制类型转换        | `short -> int`  |

## 浮点数结构与真值

**float**：32位单精度浮点数，==float阶码偏置值127==

| 1 bit | 8 bit | 23 bit |
| ----- | ----- | ------ |
| 符号s   | 阶码e   | 尾数f    |
**偏置值**：先按照无符号整数的规则解读**阶码**，在其基础上**减去127**
 - 即**阶码e**的取值范围为1~254（全0和全1有其他用途）

**尾数**：23位尾数实际上表示了24位位有效数字，*因为第一位恒为1，所以隐藏*

<span style="color:red;font-weight:bold">IEEE 754标准的规格化单精度浮点数的真值为：</span>
$$
(-1)^s\times1.f\times 2^{e-127}
$$

非规格化浮点数的真值：
$$
(-1)^s\times0.f\times 2^{-126}
$$
**重要边界**：
$$
\begin{gather*}
最小正非规格化数 = 2^{-149}\\\\
最小正规格化正数 = 2^{-126}\\\\
最大有限正数 = (2-2^{-23})2^{127}
\end{gather*}
$$

## 编码与解码

**编码**（十进制真值转浮点数）：确定符号 -> 绝对值转二进制 -> 写成$1.F\times2^e$ -> 求$E=e+127$ -> 去掉隐藏位得到F -> 拼接S E F

**例如**：将十进制-8.25转化为IEEE 754单精度浮点数格式表示：
 - 先将-8.25转化为二进制，即$-1000.01 = -1.00001\times 2^3$，，尾数部分取小数点后23位，即$00001$后补0至23位
 - 再计算阶码E，$E-127=3,E=130$，转化为二进制为$1000,\,0010$ 
 - IEEE 754单精度浮点数格式：S+E+F，即
$$
1,\,1000\,\,0010,\,0000\,\,1000\,\,0000\,\,0000\,\,0000\,\,000=C1040000H
$$
---

**解码**（二进制浮点数转十进制真值）：拆分S E F -> 判断编码类别(规格/非规格/特殊值) -> 恢复$1.F或者0.F$ -> 求真实阶指数 -> 计算真值

**例如**：求IEEE 754单精度浮点数$C640\,0000H$
 - 先将$C640\,\,0000H$ 按二进制展开
   $$
	   1100\,\,0110\,\,0100\,\,0000\,\,0000\,\,0000\,\,0000\,\,0000
   $$
 - 按照IEEE 754单精度浮点数格式划分
   |$S=1$|$E=1000\,\,1100$|$F=100\,\,0000\,\,0000\,\,0000\,\,0000\,\,0000$|
 - 因此S=1表示为负数，**阶码真值**为$1000\,\,1100-0111\,\,1111=(0000\,\,1101)_2=13$，**尾数真值**为$1+(0.1)_2=1.5$，因此该单精度浮点数的值为$-1.5\times 2^{13}$

## 注意真值用浮点数能否精确表示：检查精度

判断十进制有理数转化成二进制小数后，能否在有限位后结束，技巧如下：
 - 先把真值写成**最简分数**
 - 分母**只能**由若干个2相乘得到，二进制小数才能有限得到
 - 分母含3、5、7等其他因子，二进制小数会无限循环

| 数值              | 最简分数及分母                  | 结论      |
| --------------- | ------------------------ | ------- |
| 0.125           | $\dfrac{1}{8},8=2^3$     | 二进制有限   |
| 0.75            | $\dfrac{3}{4},4=2^2$     | 二进制有限   |
| 0.2             | $\dfrac{1}{5}$，含由因子5     | 二进制无限循环 |
| 0.3             | $\dfrac{3}{10},2\times5$ | 二进制无限循环 |
| $\dfrac{3}{12}$ | $\dfrac{1}{4}$           | 二进制有限   |
*一句话总结：==确定真值的二进制能够有限位结束后，还要检查有效数字是否能装入float的24位有效精度==*，例如：$2^{24}+1$不能精确表示，但$2^{24}+2$可以

## 注意真值用浮点数能否装下：检查范围

| ---------- | ----------- | ---------- |

| $2^{24}+1$ | 能           | 不能         |

## 浮点数大小表示

**过程**：
 - 同为正规格化数：正数按阶码、尾数顺序比较；负数按**相反**方向比较
 - 同为非正规格化数：尾数字段越大，真值越大；同为负非规格化数则**相反**
 - 任意正的规格化数**大于**任意正非规格化数；任意负规格化数**小于**任意负非规格化数
 - 一些特殊值的大小比较：
    - +∞大于所有有限数，-∞小于所有有限数，且+∞>-∞
    - +∞=+∞，-∞=-∞；但+∞<+∞，-∞<-∞均为**假**
    - +0=-0
    - NaN与其他数的大小比较为**无序**，无序不是“真假不确定”，而是两个操作数不属于<、=、>任何一种关系，NaN与自身也**不相等**

# 整数加减法、标志位与移位

## 四个标志位

**整数加减与这几个标志位的关系**：

| 标志        | 含义                      | 生成逻辑？ |
| --------- | ----------------------- | ----- |
| CF：进/借位标志 | 无符号加法产生进位<br>或无符号减法产生借位 |       |
| OF：溢出标志   | 带符号整数（补码）加减法溢出          |       |
| ZF：零标志    | 保留结果为0                  |       |
| SF：符号标志   | 保留结果的最高位                |       |
*SF只是截断后结果的最高位，当OF=1时，不能根据SF判断数学真值的正负*

四个标志位用于**整数加减法运算**，核心原因是：
 - 加法/减法（以及比较CMP）会同时产生“**结果值+进位/借位+符号信息**”，这些信息刚好能**覆盖整数运算里最常见的判断**：==是否溢出、是否为0、结果正负、无符号大小关系==
 - 因此后续很多条件分支（if/else）、循环判断都会直接依赖这四个标志位

**整数乘除运算与这几个标志位的关系**：
 - x86 `MUL/IMUL`主要规定CF、OF，==溢出时置为1==；ZF、SF通常未定义
 - x86 `DIV/IDIV`的CF、OF、ZF、SF通常未定义
 - x86 除法溢出通常不能表述为==OF置为1==

**浮点数运算与这几个标志位的逻辑关系**：（FPU）
 - 普通浮点数加减不按照整数加减规则使用CF、OF、ZF、SF
 - 浮点运算状态通常由专用状态寄存器记录
 - 具体浮点比较指令是否更新部分标志位，由ISA规定

## CMP与SUB指令的区别

*if-else语句中，经常对比两个整数的大小，在机器看来，无符号整数、带符号整数没有任何区别，都是按一套逻辑、一套电路去做减法运算，并生成标志位*

```asm
SUB A,B; 计算A-B保存结果并更新标志位
CMP A,B; 计算A-B，不保存结果，只更新标志位
```

## 移位运算

| 操作     | 补入内容   | 与乘除法的关系                    |
| ------ | ------ | -------------------------- |
| 左移k位   | 低位补0   | 未丢失有效位时等价于$2^k$            |
| 逻辑右移k位 | 高位补0   | 无符号整数等价于除$2^k$后向下取整        |
| 算数右移k位 | 高位补符号位 | 负数通常向负无穷取整，不一定等于C语言向0截断的除法 |
*-5算数右移一位得到-3，而C语言-5/2得到-2*

| 操作   | x86指令     | MIPS指令 |
| ---- | --------- | ------ |
| 左移   | `SHL/SAL` | `SLL`  |
| 逻辑右移 | `SHR`     | `SRL`  |
| 算数右移 | `SAR`     | `SRA`  |
对于x86`SHL/SAL`：CF保存最后一个被移出最高位的比特，
 - 仅当移位次数**为1**时，$OF=CF\oplus 结果最高位$，
 - 移位次数**大于1**时，OF通常未定义

# 整数乘法

## 三种实现方式

| 实现     | 核心思想       | 特点           |
| ------ | ---------- | ------------ |
| 纯软件    | 循环、移位、加法   | 无专用乘法硬件，速度较慢 |
| 加法器+移位 | 逐轮产生部分积    | 多周期，硬件适中     |
| 整列乘法器  | 并行产生并累加部分积 | 速度快，硬件开销大    |

![[带符号整数乘法电路图.png]]

相比无符号整数乘法电路，相当于在Y后多了一个**辅助位**

**开始**：
 1. 将被乘数、乘数放入X、Y
 2. 乘积寄存器P置为0，==辅助位置为0==
 3. 计数器$C_n$的初始值置为n（n为乘数的位数）

重复n轮 ==加/减法、移位==运算，直到$C_n=0$
 1. 将==乘数寄存器的最低位、辅助位==，<span style="color:red;font-weight:bold">2bit</span>送入控制逻辑进行判断
 2. 根据==寄存器Y的最低位、辅助位==，决定是$+[x]_补,-[x]_补,+0$
 3. 将【P、Y、辅助位】视为整体，<span style="color:red;font-weight:bold">算数右移</span>一位
 4. 计数器$C_n-1$
**结束流程**（$C_n=0$）
 5. 乘法运算的结果用2n位暂存（寄存器P，寄存器Y）
     - 很多计算机架构中只存低位，所以可能发生溢出

**溢出判断**：
 - 两个n bit**带符号整数**相乘，运算结果使用2n bit暂存，通常仅保留低n位作为结果
   即==若高n+1位不完全相同==，则**发生溢出**，此时<span style="color:red">可将OF标志位置为1</span>

![[无符号整数乘法电路图.png]]
**无符号乘法流程**：重复n轮（n就是乘数Y的尾数）
 1. 将==乘数寄存器Y的最低位==，送入控制逻辑判断
 2. 若**最低位为1**，则==**执行加法**==，运算结果写回**P**，进位保存至C
    若**最低位为0**，则==什么都不做==
 3. 将【C、P、Y】视为整体，==逻辑右移一位==
 4. 计数器$C_n-1$
**结束流程**（$C_n=0$）
 5. 乘法运算的结果用2n暂存
 -  在很多计算机架构中，只保留低n位作为结果，因此可能会发生==溢出==

**溢出判断**：
 - 两个n bit无符号整数相乘，运算结果使用2n bit暂存，通常仅保留低n位作为结果
   即==若高n位不全为0==，则**发生溢出**，此时<span style="color:red">可将OF标志位置为1</span>

## <span style="color:red">完整乘积与溢出</span>

两个n位操作数的完整乘积最多需要2n位，只保留低n位时：
 - 无符号乘法：全n位全0，才不溢出
 - 带符号乘法：高n位必须是低n位**符号位**的完整拓展才不溢出

若要处理溢出情况，需要在乘法指令之后，执行==溢出自陷指令==
## 复习建议

强化阶段有限掌握完整乘积、2n位机器数、高低半部分、signed/unsigned 溢出判断和三种实现方法能简答即可

除非题目要求第k轮寄存器内容时才逐轮模拟

# 整数除法

![[整数除法.png]]

**无符号整数除法**：
**开始**：
 - 将数据放入寄存器
    1. ==除数==放入==寄存器Y==
    2. ==被除数==放入==寄存器【R、Q】==并完成**零拓展**
    3. 计数器$C_n$的初始值置为n
 - 特殊情况检查
    - 如果==除数为0==，发生**除数为0异常**，停止除法运算，调出操作系统的异常处理程序
    - 如果==|被除数| < |除数|==，则 商 = 0，余数=被除数，除法器不必再执行

**步骤**：n+1轮处理（计算1+n位商）
 - **上商的规则**：如果【R】-【Y】≥ 0，则上商1，否则上商0
 - ==**第一轮**特殊处理==
    - 直接上商，若==第一位商=1==，发生**商溢出异常**，停止除法运算
    - 直接上商，若==第一位商=0==，说明不会发生商溢出，==不必保存这位商，也不让Cn--==，除法运算继续
 - 其余n轮处理
    1. 先左移，空出的位用于上商
    2. **上商**，背后的过程可能涉及加/减法
    3. 计数器$C_n--$，当计数器为0时，除法运算结束

**结束**：当计数器Cn=0时，除法运算结束
 - n bit寄存器【R】保存余数、n bit寄存器【Q】保存商

**带符号整数除法**：电路与无符号除法一样
**开始**：初始化
 - **被除数**：需要符号拓展为2n bit位
 - 除数：放入【Y】
 - 计数器Cn：初始值为n

**步骤**：n轮处理
 1. 先**左移**，空出的位用于上商
 2. **上商**
     - 由控制器根据**中间余数**与**除数**的符号结合来决定本轮做**加法 or 减法**（同号-，异号+）
     - 再根据ALU运算结果（新余数）的符号位来决定上商为1或0
     - 新余数与老余数相比：
        - **符号不变** -> **上商1**
        - **符号变** -> **上商0**
 3. 计数器$C_n--$，当为0时，除法运算结束

**结束**：当计数器Cn=0时，除法运算结束，n bit寄存器【R】保存余数；n bit寄存器【Q】保存商
 - 原被除数、除数**异号**，所以商Q需要取补（全部位按位取反，末尾+1）

**特殊情况判断**：
 - 可直接得到除法运算结果？
    - 如果==|被除数| < |除数|==，则==商=0==，==余数=被除数==，除法器不在执行
 - 除数是否为0？
    - 如果除数为0，发生除数为0异常
 - 是否可能发生溢出？
    - **考试要点**：对于补码的单精度除法，仅“绝对值最大的负数÷-1”，才有可能发生商溢出异常

## 手算推演除法运算结果
$$
x=qy+r,|r|<|y|
$$
一句话总结：
 - ==**无符号除法** = 小学除法（**商向下取整、余数非负**）==
 - ==**带符号除法**需要额外约定**商向0截断、余数与被除数同号**==

*a=-5，b=2，a/b，商寄存器：-2，余数：-5 =-2(q)×2(y) + r，即余数r = -1*

## 几种除法异常

**情况**：
 1. 无符号数/带符号数，注意：==除数为0==
 2. 带符号数注意：绝对值最大负数/-1，导致商超出正数补码范围
 3. 单字长被除数 vs 双字长被除数的无符号除法
     - 对于 “ n 位无符号被除数 ÷ n 位非零无符号除数 -> n 位商”，除数为0仍然会触发异常
     - 对于 “ 2n 位无符号被除数`R:Q` ÷ n 位非零无符号除数Y -> n 位商”：
        - `R<Y`时商**可装入**n位
        - `R>=Y`时商**溢出**

## 被除数拓展为双倍字长【R:Q】的规则

**无符号被除数**：**零拓展** -- Q=被除数，R全0

**带符号被除数**（补码）：**符号拓展** -- R与被除数符号位一致，非负全0、负数全1

# 浮点数加减

## 基本过程

==检查特殊值 -> 对阶 -> 尾数加减 -> 规格化 -> 舍入 -> 再次规格化 -> 检查阶码==

对阶遵循“小阶向大阶看齐”，可能出现大数吞小数
对阶右移时保留G、R、S位

就近舍入、恰好中点取偶时，进位条件为$G\wedge(R\vee S\vee L)$，其中L为保留部分最低位

### 舍入判断

为保证精度，现在截断尾数的时候引入三个辅助位：
 1. 保护位：紧邻尾数的第一位，用于初步判断舍入信息
     - 保护位为**0**，则**直接舍弃**
     - 保护位为**1**
        - 舍入位==**或**==粘滞位为**1**，尾数直接+1
        - 舍入位==**和**==粘滞位均为**0**，则在尾数末尾为**奇数**时，尾数+1
 2. 舍入位：位于保护位之后，与保护位和粘滞位共同构成舍入信息
 3. 粘滞位：只要舍入位后至少存在一个1，则值为1

## 浮点数加减运算风险表

| 阶段   | 风险或现象          | float加减示例                             | 结论             |
| ---- | -------------- | ------------------------------------- | -------------- |
| 对阶   | 低位丢失、大数吞小数     | $2^{100}+1=2^{100}$                   | 小操作数移出有效精度     |
| 尾数相加 | 尾数产生进位         | `1.5f+1.5f=3.0f`                      | 需要右规，但不自动上溢    |
| 尾数相减 | 有效数字大量抵消       | $1+2^{-23}-1=2^{-23}$                 | 结果需要多次左规       |
| 右规   | 阶码+1，可能上溢      | `FLT_MAX+FLT_MAX`                     | 阶码越界，得到+∞      |
| 左规   | 阶码减小，可能进入非规格化区 | `00800000H-007FFFFFH=00000001H`       | 结果为最小非规格化数     |
| 舍入   | 舍入进位可能再次右规     | `3FFFFFFFH+33800000H=40000000H`       | 中点取偶后得到2.0     |
| 最终封装 | 产生无穷、非规格化数或0   | `FLT_MAX+FLT_MAX`;边界相减;`1.0f+(-1.0f)` | 分别得到+∞；非规格化数；0 |

## 典型示例 两个最大float相加

设$x=y=(2-2^{-23})2^{127}$：阶码相同 -> 尾数相加产生进位 -> 右规 -> 阶码加1 -> 阶码超出范围 -> 结果为+∞

# 错题知识点

## 选择题

正确率：61/82 = 74%

**知识点**：
 1.  计算机系统内部均是二进制编码的，原因有下：
     1. 二进制只有两种状态，使用两个稳定状态的器件就可表示，成本低
     2. 二进制位1、0与逻辑真、假对应
     3. 二进制编码和运算规则都很简单
 2. 运行如下代码后ui的真值为？`short si = -32767;unsigned int ui = si;`（本题算错了）
     - -32767的补码表示为8001H，转为无符号整数需要符号拓展FFFF8001H=$2^{32}-1-(2^{15}-1)+1=2^{32}-2^{15}+1$
 3. （2023真题）x,y为int类型，`x=100,y=200`，执行x-y后OF和CF为0、1，那么当`x=10,y=-20`时，执行该指令后的OF和CF为？
     - OF为有符号数溢出位，显然没有溢出，则为0，CF只与无符号数有关，$CF=C_{out}\oplus sub$，此时没有产生进位$C_{out}=0$，由于sub为减法，所以$sub=1$，则 CF=1
 4. 快速阵列乘法器的核心设计思想是==并行累加部分积==，所以其基本部件仅包含**全加器和与门**
 5. 关于浮点数加减
     - 对阶不会引起阶码上溢或者下溢
     - 右规和尾数舍入都可能引起阶码上溢
     - 左规可能引起阶码下溢
     - 尾数溢出时结果不一定溢出
 6. **边界对齐原则如下**：
     1. 普通数据成员对齐规则
         - 第一个数据成员放在offset为0的地方，以后每个数据成员存储的起始位置要从该成员大小的整数倍开始
     2. 结构体数据成员对齐规则
         - 如果一个结构里有某些结构体成员，则该结构体成员要从其内部最大元素大小的整数倍地址开始存储
     3. 结构体大小对齐规则
         - 结构体大小就是sizeof的结果，必须是其内部成员中最大的对齐参数的整数倍

# 转移指令

**无条件转移指令**：`jmp`
```asm
jmp <地址>
jmp 128 #地址可由常数给出
jmp eax #地址可来自寄存器
jmp [999] #地址可来自于主存
jmp NEXT #地址可用“标号”确定

jmp NEXT
mov ecx,ebx
NEXT:       #有冒号，名字可自己取
mov ecx,eax
```

**条件转移指令**：
 - 先比较两个数：`cmp a,b`
 - jump when equal，==🟢a\==b跳转==
    - `je <地址>`
 - jump when not equal，==🟢a!=b跳转==
    - `jne <地址>`
 - jump when gather than，==🟢a>b跳转==
    - `jg<地址>`
 - jump when gather than or equal to，==🟢a>=b则跳转==
    - `jge <地址>`
 - jump when less than，==🟢a\<b跳转==
    - `jl <地址>`
 - jump when less than or equal to，==🟢a\<=b跳转==
    - `jle <地址>`

回顾：在数据的表示与运算中有
> CMP A,B：计算A-B，不保存结果，只更新标志位

所以汇编流程为：
```asm
cmp eax,ebx
jg NEXT   # eax>ebx就跳转
```

## 循环

用条件转移指令实现循环，需4步
 1. 循环前的初始化
 2. 是否跳过循环
 3. 循环主体
 4. 是否继续
```cpp
int result = 0;
for(int i=1;i<=100,i++){
	result += i;
}//求1+2+...+100
```
用汇编实现如下：
```asm
# 循环前初始化
mov eax,0     # result
mov edx,1     # i

# 是否跳过循环
cmp edx,100   # 比较i和100
jg L2         # 若i>100，则跳转至L2

L1:           # 循环主体

# 循环主体
add eax,edx
inc edx       # i++

# 是否继续
cmp edx,100   # i和100比较
jle L1        # i<=100,跳转至L1

L2:           # 跳出循环主体
```

# 函数调用的机器级表示

*未深入考察，但有趋势*

函数的栈帧Stake Frame：保存函数大括号内定义的**局部变量**、保存**函数调用的相关信息**

*x86处理器中通常将PC，称为IP，Instruction Pointer*
函数调用：`call<>`
 1. 将==🔵IP旧值==压栈保存
 2. 设置==IP新值==，无条件转移至被调用函数的第一条指令
函数返回：`ret`
 - 从函数的栈帧顶部找到==🔵IP旧值==，将其出栈并恢复IP寄存器

==🔴ebp==：指向当前栈帧的==🔴底部==
==🟠esp==：指向当前栈帧的==🟠顶部==

```cpp
int caller(){
	int temp1 = 125;
	int temp2 = 80;
	int sum = add(temp1,temp2);
	return sum;
}

int add(int x,int y){
	return x+y;
}
```

```asm
caller:
# 以下两条指令等价于 enter
push ebp         # 保存上一层函数的栈帧基址(ebp旧值)
mov ebp,esp      # 设置当前函数的栈帧基址(ebp)新值 

sub esp,24
mov [ebp-12],125 # temp1
mov [ebp-8],80   # temp2
mov eax,[ebp-8]
mov [esp+4],eax  # sum
mov eax,[ebp-12]
mov esp,eax

call add
mov [ebp-4],eax
mov eax,[ebp-4]
leave
ret

add:
push ebp
mov ebp,esp

mov eax,[ebp+12] # y
mov edx,[ebp+8]  # x
add eax,edx
leave

# leave等价于
# mov esp,ebp 让esp指向当前栈帧的底部
# pop ebp     将esp所指元素出栈，写入ebp

ret
```

## 栈帧的内容

地址由高到低依次是：

**上一层栈帧基址**：每个函数开头都会执行`push ebp`和`mov ebp,esp`
 - **一定存在**，用于恢复上一层栈帧

**局部变量**：C语言中越靠前定义的局部变量越**靠近栈顶**
 - **不一定存在**：有些函数可能不定义局部变量

未使用的区域：栈帧大小为16B的整数倍，因此可能产生未使用区域
 - **不一定存在**：其他部分刚好是16的整数倍时

**调用参数**：参数列表中越靠前的参数越靠近栈顶
 - **不一定存在**：有些函数调用不传参

==🟣IP(返回地址)==：函数调用时，call指令将IP寄存器值压栈保存
 - **一定存在**(发生调用时)，但凡调用其他函数，就必须记录返回地址

## 总结

**对于调用者而言**：
 - 保存必要的寄存器
    - eax，edx，ecx
 - 将调用参数写入当前栈帧的顶部区域
    - push，mov实现
 - 执行`call`指令
    - 返回地址压入栈顶、并跳转到被调用函数第一条指令
 - 使用返回值
    - 通过eax寄存器

**对于被调用者而言**
 - 保存上一层函数栈帧，设置当前栈帧
    - enter指令，*或其等价写法*
 - 初始化局部变量
    - \[ebp -4\]、\[ebp-8\]
 - 一系列逻辑处理
 - 向上层函数传递返回值
    - 通过eax寄存器
 - 恢复上一层函数栈帧
    - leave指令，*或其等价写法*
 - 执行ret指令
    - 从栈顶找到返回地址，出栈并恢复IP值

## 结构冒险及其处理

==IF取指== -> ID译码/取数 -> EX执行/计算地址 -> ==M访存== -> WB写回
 - 若一条指令同时再IF和M阶段使用主存/Cache

| 时钟  | 1      | 2      | 3      | 4      | 5      | 6     | 7     | 8     | 9   |
| --- | ------ | ------ | ------ | ------ | ------ | ----- | ----- | ----- | --- |
| 指令1 | ==IF== | ID     | EX     | ==M==  | WB     |       |       |       |     |
| 指令2 |        | ==IF== | ID     | EX     | ==M==  | WB    |       |       |     |
| 指令3 |        |        | ==IF== | ID     | EX     | ==M== | WB    |       |     |
| 指令4 |        |        |        | ==IF== | ID     | EX    | ==M== | WB    |     |
| 指令5 |        |        |        |        | ==IF== | ID    | EX    | ==M== | WB  |

比如在时刻4，指令1和指令4同时访问主存，触发结构冒险
 1. 可以通过**硬件阻塞**来解决结构冒险，即将指令4延后三个时钟周期
 2. 将**指令Cache**和**数据Cache==分离==**

做题时若是五段式指令流水线，则默认是指令、数据Cache分离（除非特殊说明）

## <span style="color:red;">数据、控制冒险</span>

**最常考**

|         | IF取指 | ID译码/取数               | EX执行/计算地址        | M访存         | WB写回             |
| ------- | ---- | --------------------- | ---------------- | ----------- | ---------------- |
| LOAD指令  | 取指令  | ==译码、取数<br>(可能读寄存器)== | 计算访存地址           | 从主存读数据      | ==🟠将数据写回某个寄存器== |
| STORE指令 | 取指令  | ==译码、取数<br>(可能读寄存器)== | 计算访存地址           | 往主存写数据      | --               |
| 转移类指令   | 取指令  | ==译码、取数<br>(可能读寄存器)== | 计算访存地址           | ==🟢更新PC值== | --               |
| 运算类指令   | 取指令  | ==译码、取数<br>(可能读寄存器)== | 执行<br>（算数、逻辑运算等） | --          | ==🟠将数据写回某个寄存器== |


==黄色：表示可能导致**数据冒险**==
==🟢表示可能导致**控制冒险**==

==**数据冒险**==比如：若进行
```asm
I1：985 -> R1   # R1=985
I2：R1+1 -> R2  # R2=986
```
但引入指令流水线后

| 时钟  | 1   | 2   | 3                  | 4   | 5                     | 6   |
| --- | --- | --- | ------------------ | --- | --------------------- | --- |
| 指令1 | IF  | ID  | EX                 | M   | **WB**<br>（此时才将985写入） |     |
| 指令2 |     | IF  | **ID**<br>（读出错误数据） | EX  | M                     | WB  |

**解决方法**：让`I2`阻塞三个时钟，等数据写回后，在进行读操作

==🟢控制冒险==比如：若进行
```asm
I1:            # 若恰为转移类指令 -> 改变PC值
I2:
I3:
```
而改变PC值是在第四个M访存阶段才改变的

### 数据冒险的分析和处理

**是否存在**：
 - 核心特点：==🟠两条指令，前“写”后“读”同一寄存器==
 - 分析方法：从第一条指令开始，结合注释，观察该指令“写”了某个寄存器，并观察后续相邻的3条指令是否“读了”同一寄存器，若发现此类情况，说明存在**数据冒险**

**解决方法**
 - ==🟣**硬件阻塞**==：将“读寄存器指令”的ID段硬件阻塞若干时钟，==🟣确保其ID段在“写寄存器指令”的WB段之后==
 - ==🔵**转发（旁路）技术**==

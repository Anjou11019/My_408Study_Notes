##### 10.22

逻辑格式化中，确定文件系统格式：UFS（**混合索引**，UNIX）、FAT（**显式链接**，早期Windows）

操作系统引导：
 1. CPU从一个特定主存地址开始，取指令，执行ROM中的引导程序（先进行硬件自检，再开机）
     - CPU -> ROM(BIOS)：包含ROM引导程序，即**自举程序**
 2. 将磁盘的第一块 -- 主引导记录读入内存，执行磁盘引导程序，扫描分区表
     - 主引导记录MBR（磁盘）：包含磁盘引导程序和分区表
 3. 从活动分区（又叫主分区，即安装了操作系统的分区）读入分区引导记录，执行其中的程序
     - 引导记录PBR（C盘）：负责找到启动管理器
 4. 从根目录下找到完整的操作系统初始化程序并执行，完成开机的一系列动作
     - 根目录（C盘）

则一块可存$2^{12}/2^7=2^5=32$个

假设A有66个文件，则其有66个FCB，由于是**顺序存储**，则其需要5、6、7号块存放这66个FCB
 - 第7块中，空闲 4KB-128B

假设使用一块来存储**位示图**，$4KB=2^{12}\times2^3bit$，即共可表示$2^{15}$个块

==一个目录文件由多个**目录项FCB**组成==
所谓FCB，可以抽象成struct结构体
```cpp
struct FCB{
	char name[100];//文件名
	int 起始块号,结束块号;
	int 文件大小; //多少字节
	文件类型 //普通或者目录
	...
}
```

**问题**：假设根目录存放在4号块中，若其中的文件越来越多，导致4号块无法存放所有文件的FCB，但此时**5号块存放的是文件A的FCB**，则需要将A的文件统一后移
 - 所以顺序存储，一般只有只读文件系统使用

#### FAT

FAT文件分配表
 - 会用固定的0号块，存储操作系统的引导程序
 - 0号块的后边，1，2，3号块存储FAT

FAT如下图示例：
![[图3FAT.png]]

FAT中，每个表项的大小会对文件系统产生影响
 1. 对文件系统支持的**最大磁盘块数**有影响，若每个表项16bit，则最多只能支持$2^{16}$个块号
 2. 对**FAT表**有影响，每个 表项的大小 × 表项的数量 = FAT表的大小

**操作系统使用FAT**：
 - 开机时，就把**整个FAT读入内存**，系统运行中，该表一直会**常驻内存**，也就是说查FAT表不需要**读磁盘**，内存中本就有整个表
 - 系统运行过程中，访问文件，则
    - 首先找到这个文件对应的目录项
    - 从目录项中找到文件的起始块号
    - 根据起始块号查FAT表

根目录中只记录了**文件B**的**文件大小**以及**起始块号**
 - 文件B：10 -> 12 -> 8
 - 由于只记录了起始块号，其余的块则需要查询FAT表

假设B中一个需要连续的读10、8号块的内容，**结合FAT表**，则**不需要**读第12号块

**文件A如下**：
![[图3文件A.png]]

假设目录**文件A**需要3个块，5、6、7号块，==其**不需要**占用连续的三个块**
 - 目录文件中存在"."，和".."，一个表示当前目录，一个表示上级目录
 - "."，的起始块号为5
 - ".."，的起始块号为4，即根目录的位置

文件A占用的块数 = $\dfrac{目录项的数量\times每个目录项的大小}{块大小}$

读取/A/Dm到内存的过程：根目录常驻内存

 5. 找到Dm的目录项，确定Dm的起始块号为m，结合FAT表即可知道Dm的全部块号，将Dm的块读入内存即可

**思维导图**：
 - 内存管理概念
    - 内存管理的基本概念
       - 逻辑地址与物理地址的概念
          - 逻辑地址
             - 进程具有从0开始连续编号的地址，不同进程可以有相同的逻辑地址
          - 物理地址
             - 内存的从0开始的连续编号的地址，不同进程相同的逻辑地址可以映射到主存不同的物理地址
          - 操作系统通过内存管理软件（MMU）将进程使用的逻辑地址转换为物理地址
       - 程序的链接与装入
          - 编译：将源码编译为若干目标模块
            链接：将多个目标模块，以及需要的库函数链接一起，形成完整的装入模块
            装入：将装入模块放入内存
          - 装入方式（==图3.2==）
             - 绝对装入
                - 程序的逻辑地址与实际内存物理地址完全相同，只适用于单道程序
             - 可重定位装入（==静态重定位==）
                - 装入时将程序中的逻辑地址转换为物理地址，运行期间不能在内存移动
             - 动态运行时装入（==动态重定位==）
                - 程序装入内存时，程序中依然保存的是相对地址，运行时才把程序中的地址转为绝对地址，程序在内存中可发生移动
          - 链接方式
             - 静态链接：程序运行之前，先将各个目标模块连接成完整的装入模块
             - 装入时动态链接：边装入边链接
             - 运行时动态链接：不需要的目标模块先不调入内存，执行时要用到再链接
       - 进程的内存映像
          - 操作系统内核区
          - 用户栈区：函数调用相关信息，函数中的局部变量
          - 共享库的存储映射区：printf函数的代码
          - 堆区：malloc申请的空间
          - 读/写数据：全局变量和静态变量
          - 只读代码：程序对应的机器指令
       - 内存保护
          - 确保每个进程都有一个单独的物理地址空间，进程在运行时的地址访问范围不能超过自己的物理地址空间范围
       - 内存共享
          - 内存映像中的只读代码
          - 可重入代码：允许多个进程同时访问但不允许任何进程修改
       - 内存分配与回收
    - 连续分配管理方式
       - 单一连续分配
          - 内存中仅有一个程序，==有内部碎片，无外部碎片==
       - 固定分区分配
          - 将内存划分为若干固定大小的分区，每个分区存放一个程序
          - 分区大小相等
          - 分区大小不等
          - ==有内部碎片，无外部碎片==
       - 动态分区分配
          - 根据进程实际需要，动态为其分配内存，分区大小等于进程需要的大小
          - ==无内部碎片，有外部碎片==，需要通过紧凑技术，对进程移动和整理
       - 动态分区分配算法
          - 首次适应算法
             - 空闲分区按**地址递增**进行分配
          - 临近适应算法
             - 分配内存时从上次查找结束的位置开始继续查找
          - 最佳适应算法
             - 空闲分区按容量递增进行分配，**性能查，留下很小的难以利用的块，产生==最多==的外部碎片**
          - 最坏适应算法
             - 空闲分区按**容量递减**进行分配
    - <span style="color:red;font-weight:bold">非连续分配管理方式</span>
      概念很多，涉及很多计算
        - <span style="color:red;font-weight:bold">页式管理</span>（==重要，多看书，多总结，多做题==）
           - 页面和页框
            页号和页框号
           - 逻辑地址结构：页号+页内偏移量
           - 页表（页表也在内存）
              - 每个进程有一张自己的页表
              - 页表项构成：**页号+页框号**，页号是隐含的
              - 页表的作用：实现页号到物理块号的地址映射
              - 根据页表起始物理地址和页号，计算其对应页表项的物理地址
                类比根据数组首地址和数组下标，计算数组某一个元素的地址
           - 地址变换流程（==图3.9==）
              - 根据页表项物理地址访问页表
              - 根据地址变换后的物理地址，访问需要的数据
              - 两次访存
           - 页表寄存器（PTR）
              - 存放页表起始物理地址和页表长度
              - 页表起始物理地址用于计算任一个页表项的物理地址
              - 页表长度用于判断地址越界
           - 地址变换流程的十进制分析
           - 思考：如何确定页表项的大小
           - 具有块表的地址变换流程，需结合==**计组3.6**==，结合TLB映射方式进行查找快表
           - 两级页表（==综合性较强==）
              - 逻辑地址结构：页目录号+页号+页内偏移
              - 页目录表（外层页表）、页目录项、页目录号（一级页号）
              - 页表（二级页表）、页表项、页号（二级页号）
              - 页目录表的页目录项中存放的是二级页表所在的页框号
              - 页目录表和二级页表的表项物理地址计算
              - 在采用二级页表的分页系统中，CPU页表基址寄存器存放的是当前进程的一级页表的起始物理地址
              - 多级页表的优点：减少页表所占的连续内存空间
              - 地址变换过程
                 - 根据页目录号访问页目录表
                 - 根据页号访问页表
                 - 根据页表中的页框号和页内偏移量拼接后的物理地址，访问需要的数据
                 - 三次访存
        - 段式管理
            - 分页对用户完全透明，分段需要人为的根据程序功能进行划分
              分段对用户可见
            - 每个段大小可以**不相等**，灵活划分，方便实现共享
            - 分段的逻辑地址结构：段号+段内偏移量
              段内偏移量按最大的段来计算位数
              在分段系统中，段号和段内偏移量必须由用户显式提供，无法计算
            - 每个进程有一张自己的段表
              段表：==段号+段长+本段在主存的起始物理地址和段号==，计算出相关段表项的物理地址，然后访问相关段表项的内容
              *段表放的是==起始物理地址==，页表放的是==页框号==，页框号需要乘以页框大小才是对应内存起始物理地址*
            - 段表寄存器：存放段表的起始物理地址+段表长度
            - 地址变换流程：==图3.16==
              分页只需**一次**越界判断，分段需要**两次**越界判断
              *查完段表不是按分页那样去拼接，而是拿段表中的段的起始物理地址和段内偏移量进行相加*
            - **本质**：
               - 分页：页表得到的是页框号，页框号和偏移量拼接，背后的意义就是页框号×页框大小，得到页框起始物理地址，再加上页内偏移量
               - 分段：段表得到的就是段的起始物理地址，直接加上段内偏移量即可
            - 分页和分段的对比（==27版 图3.16旁==）
            - 段的共享和保护
        - 段页式管理（==未考过，综合性强==）
	        - 进程的地址空间被分成若干逻辑段，每个段再分成固定大小的页面
	          内存地址空间需要将其分成若干和页面大小相同的物理块（页框），对内存的分配以物理块为单位
	        - 逻辑地址结构：段号+页号+业内偏移量
	        - 在段页式系统中，每个进程的段表只有一个，页表可能有多个
	        - **段表的内容**：段号，页表长度，页表起始地址
	          **页表的内容**：页号、页框号
	          先查段表找到对应页表，再查页表得到页框号，最后依然是页框号和页内偏移量拼接得到物理地址
	        - 段页式系统中需要用到段表寄存器和页表寄存器
	        - 地址变换流程：==图3.19==
	        - 将段页式系统和分页、分段以及二级页表进行对比
	           - **分页**：段页式系统和分页一样，最后都是根据页表的页框号和页内偏移量进行拼接
	           - **分段**：都有查段表的流程，但分段和段页式中，段表的内容不一样，作用一样
	           - **二级页表**：查完页目录表或者段表后，接下来都是查一次页表；段页式和二级页表都有多个页表
 - 虚拟内存管理
    - 虚拟内存的基本概念
       - 局部性原理
          - 时间局部性
          - 空间局部性
       - 虚拟存储器定义：仅需将程序当前运行所需的页面装入内存，进程的逻辑空间比实际分配的物理地址空间小得多，用户感觉比实际物理内存大
    - 请求分页管理
       - 含义：当访问的页面不存在时，通过请求调页功能将其从外存调入到内存；内存不够时，需要通过页面置换将暂时不用的页面换出到外存
       - 请求分页页表：页号，页框号，状态位，访问字段，修改位，外存地址
       - 缺页中断机构
        缺页处理流程
         - 缺页，**内中断**，执行缺页中断处理程序
         - 进程阻塞，从磁盘读所缺页面，调页完成后唤醒进程
         - 若有空闲页框，进行分配，并修改页表项
         - 若无空闲页框，需通过页面置换算法选择页面淘汰
         - 被置换的页面如果期间发生了修改，还需写回外存
         - ==图3.21==
    - 页框分配
       - 驻留集：给一个进程分配的页框的集合
        工作集 ：进程在某段时间间隔内，要访问的页面集合
        *二者的联系是：给进程分配的驻留集需要大于等于工作集，否则经常会缺页*
       - 内存分配策略（==注意术语==）
          - **固定分配局部置换**
             - 分配的页框固定，缺页时在已分配的页框中进行置换
          - **可变分配全局置换**
             - 发生缺页时，从系统的空闲页框队列中取出页框分配进程，但是会盲目的给进程增加物理块
          - **可变分配局部置换**
             - 发生缺页时，先在已分配的页框中进行置换，若频繁发生缺页，则会给进程分配新的页框
    - **页置换算法**
      需要根据页面访问序列，置换算法分析==缺页次数，置换次数，命中次数==
        - **最佳置换算法OPT**：将后续**最长时间**不再访问的页面置换
        - **先进先出置换算法FIFO**：将**最早**放入内存的页面置换，==会有Belady异常==
          Belady异常：给进程分配的物理块增多，缺页次数不减反增
        - **最近最久未使用算法LRU**：将==最久==未使用的页面置换
        - **简单的CLOCK置换算法**
           - 设置访问位，页面首次装入或者被访问，置为1
           - 需要置换时，按指定方向进行扫描，将**访问位为0**的页面置换；若为1，修改为0，继续扫描
           - 某一页被替换时，指针指向被替换页面的下一页，待下次需要置换时，从那里开始扫描
           - 细节较多
        - **改进的CLOCK置换算法**
           - 除了访问位，还新增==修改位==
           - 第一轮扫描：寻找既没访问，也没修改的页面==淘汰==
            第二轮扫描：寻找未访问，但修改的页面淘汰，并将扫描过的页面的==访问位设为0==
            第三轮扫描：重复第一轮
            第四轮扫描：重复第二轮
            最多四轮扫描，一定能找到页面进行置换
           - 依然适用的规则
              - 页面首次装入或被访问时，置为1
              - 某一页被替换时，指针指向被替换页面的下一页，待下次需要置换时，从那里开始扫描
           - 页面被置换的顺序
              - 访问位为0，修改位为0
              - 访问位为0，修改位为1
              - 访问位为1，修改位为0
              - 访问位为1，修改位为1
    - 抖动和工作集
       - 抖动：进程刚换出的页面，马上又被换入，刚换入的页面马上又被换出
        根本原因是给进程的页框太少
       - 工作集：进程在某段时间间隔内，要访问的页面集合 
    - *了解概念*
       - 页框回收
       - 内存映射文件
       - 虚拟存储器性能影响因素及改进方法

操作系统的设计者（Linux）对内存的每一个片区做什么事做了规定，而1个进程不会占用全部内存空间，其中有很多空白的区域，当进程需要时，操作系统将会对进程分配**页面**
 - Windows是另外一种划分，但408考试一般讨论Linux

操作系统的内核区代码，是所有进程**共享的**

==**举例**==：（2025真题）
内存：（地址由高到低）
 1. 操作系统内核区
     - 内核代码、内核数据结构等
 2. 用户栈⬇
     - 由各函数的栈帧组成，包含各个局部变量、函数调用相关的信息
 3. 空区
 4. 共享库的存储映射区⬆
     - 如：printf函数的代码
 5. 用户区
 6. 堆
     - malloc分配的区域
 7. 读/写数据
     - 全局变量、静态变量
 8. 只读代码/数据
     - 程序指令、只读数据
 9. 未使用区
对于以下代码：
```c
char *ptr;
void main(){
	int length;
	ptr = (char *)malloc(100);
	scanf("%s",ptr);
	length = strlen(ptr);
	printf("length = %d\n",length);
	free(ptr);
}
```
问：
1. 上述程序执行时，其进程控制块处于哪个位置？执行scanf等待键盘输入时，该进程处于什么状态？
    - 进程控制块在内核区
    - 等待键盘键入时，进程处于阻塞态
2. main函数的**代码**位于哪个区域？其直接调用的哪些函数的功能需要通过执行驱动程序实现？
    - main函数的==**代码**==位于只读代码段
    - 其直接调用的scanf和printf需要通过执行驱动程序实现
       - scanf和printf涉及到IO设备，需要设备驱动程序进行相应处理
3. 变量ptr被分配在哪个区域？若变量length没有被分配在寄存器中，则会被分配在哪个区域？ptr指向的字符串位于哪个区域？
    - 变量ptr被分配在可读写数据段（ptr是**全局变量**）
    - length会被分配至**用户栈main函数的栈帧里**
    - ptr指向的字符串位于**运行时堆**中（malloc，属于用户申请的区域）
特别的：假设代码变为：
```c
char *ptr;
add(int n){
	int m;
	n++;
}
void main(){
	int length;
	ptr = (char *)malloc(100);
	scanf("%s",ptr);
	length = strlen(ptr);
	printf("length = %d\n",length);
	free(ptr);
	add(length);
}
```
此时add函数中使用的参数n存在什么区域？add中的变量m存在哪个区域？
 - n存在**用户栈**中main函数的栈帧里
 - m存在**用户栈**中add函数的栈帧里

# 物理内存和虚拟地址空间

假设**虚拟地址空间**（0000 000H ~ FFFF FFFH），即
\<虚拟页号 16bit，页内偏移量 12bit\>

**物理内存**：页框大小为4K，页框总数为4K个，即
物理地址 = \<页框号 12bit，业内偏移量 12bit\>
![[图二物理内存.png]]

虚拟地址空间与内存空间并非一一对应，有时候虚拟地址的页面可能并未**调入内存**，此时会发生缺页
 - 缺页：**查页表**的时候发现

![[图三一级页表.png]]

*注：如果采用“一级页表”，整个页表在内存里必须物理上**连续存放**，这样会导致存储页表需要占用连续的很多个页框*
 - 设页表项4B，一个页表占$2^{16}\times 4 = 2^{18}B \rightarrow 2^6=64$个==连续页框==
   假设为32号（020H）页框~95号（05FH）页框

一个函数被调用的第一条指令一般是：`push ebp`（保存上层函数的栈顶指针）

main调用f1函数 $\Rightarrow$ Call指令
 - 存旧的PC值
 - 新PC -> 0007 000H（VA）
    - 下一条指令的取指阶段，就需要访问Call指令调用的函数第一条指令的VA
    - 0007H为VPN虚页号，从$页表始址 + 页号 × 页表项大小 = VPN$
    - 此时==有效位 = 0==，说明发生缺页，通过查页表发现，此时该页面在外存的20号块中
    - 进行调页，并将有效位置为1，修改页框号（假设为FFFH）
 - 此时f1的==第一条指令==的**PA**（物理地址）= FFF 000H

**TLB命中**：
假设访问虚拟地址==VA = 0003 000H==
 1. 将其拆分为**虚拟页号**==0003H==和**页内偏移量**==000H==
 2. TLB有效位为1，TLB命中，此时页框号为012H，即完整的==PA = 012 000H==

**TLB未命中**：
假设访问==VA = 0007 000H==
 1. 将其拆分为虚拟页号==0007H==和页内偏移量==000H==，查TLB表
 2. 此时TLB有效位为0，TLB未命中
 3. 则用虚拟页号查页表，将其虚拟页号拆分为**页目录号**==00H==和**页号**==07H==
 4. 此时页目录表中==有效位 = 1==，==页框号 = 00DH==，说明二级页表在物理内存为00DH对应的页框中，查询二级页表
 5. 但二级页表中==有效位=0==，发生**缺页**，进行调页
 6. 之后将有效位置为1，页框号置为调页之后的FFFH
 7. 此时将其数据**复制**进==TLB中==，**即将有效位置为1，页框号置为FFFH**

不难发现，对于进程P1，P2，其内核区数据的==VA = FFF9H、FFFAH、FFFBH==，但内存中只有一份内核区数据，分别存放在==页框号 = 01DH、01FH、FF1H==中

假设进程PCB1、PCB2、PCB3均存放在==VA = FFFBH==，PCB本质为struct结构体，其中存放有==页表始址==，FFFBH中可能存放就绪队列，FFF9H中可能存放键盘驱动程序，FFFAH可能存放某中断处理程序
```C
struct PCB{
	int pid;
	int state;//就绪态、阻塞态、运行态...
	int PriorityNumber;//调度优先级
	//还存放有页表始址
}
```
显然==VA = FFF9H、FFFAH、FFFBH==中的各种数据，没有必要P1，P2各存一份，对于整个系统而言，只需要有一份即可

即可以用页表实现进程间共享数据，即**逻辑上**看进程的内核区数据各算各的，但**物理上**看进程内核区的数据映射到了同一个地方

这种映射方式即可实现**进程间通信**，只需使用**系统调用：信箱等**方式，P2传给P1的数据只需要将其存放到P2内核区的某一个地方，此时从物理上看，P1已经收到了相应的数据了，操作系统用系统调用的方式，将内核区的数据复制到P1对于的**用户区的页面**
 - *也可使用系统调用，将P1，P2用户区的其中几个页面映射到**同一片**物理地址中，实现进程间通信，可以使用==PV操作==控制P1，P2对共享页面的读写*

数组在连续存放的意思是==数组在逻辑地址上连续==，==其所在物理地址可能不在连续的页框中==

# 错题知识点

## 选择题

正确率：97/123 = 78.9（其中：概念题：25/34，考点题：72/89，真题正确率：26/33）

**知识点**：
 1. 可重定位分区存储管理采用的地址转换公式：==基址寄存器值 + 逻辑地址==
 2. 存储管理功能包括：存储分配、地址变换、存储扩充、存储共享与保护
 3. 基本**分页**管理：==无**外部**碎片，可能有**内部**碎片==
    基本分段管理：==有**外部碎片**，无**内部**碎片==
 4. 虚拟存储技术是==补充相对地址空间的技术==
 5. 虚拟内存管理中，地址变换机构将逻辑地址变换为物理地址，形成该逻辑地址的阶段是==链接==
     - 编辑阶段：用户源程序中的地址，常用的表示是变量符号
     - 编译：编译后形成的虽然也是逻辑地址，但是是**各个模块**的逻辑地址，并不是将该地址转换为物理地址
     - 链接：链接后形成整个程序的逻辑地址，才会在装入阶段转换为物理地址
 6. 在可变分区存储管理中，主要是利用==移动技术==来利用碎片
 7. **伙伴算法**：内存管理算法，用于管理大小相等的内存块，当一个内存块被分配时，它的伙伴将被标记为未使用。当回收内存时，若两个大小相等的空闲分区相邻，它们可以合成一个更大的空闲分区，以便更有效的使用内存
 8. （2021真题）在采用二级页表的分页系统中，CPU页表基址寄存器中的内容是==**当前进程的一级页表的起始物理地址**==
 9. （2023真题）虚拟地址空间的大小**不受**外存空间的影响，**也不受**内存空间的影响，而是由CPU的寻址范围决定的，内存和磁盘大小仅决定**虚拟存储器实际可用容量的最大值**
 10. （2025真题）在页式虚拟存储管理系统中，确定进程正常运行所需的**最少页框数**时，需考虑==指令系统支持的寻址方式==
      - 指令的寻址方式决定了单条指令可能访问的内存范围，寻址方式越复杂，需要的页框数越大
 11. （2022真题）页缓冲队列的长度不会影响系统缺页率

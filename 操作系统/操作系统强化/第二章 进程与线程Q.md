              - 无需交替进入，但可能同时进入临界区，可能违背**忙则等待**

 - <span style="color:red;font-weight:bold">死锁</span>
    - 死锁的基本概念
       - 多个进程因竞争资源而造成的一种僵局（互相等待对方手里的资源），使得各个进程都被阻塞，各个进程均无法向前推进
       - <span style="color:red;font-weight:bold">死锁的四个必要条件</span>
          - **互斥**
          - **不可剥夺**
          - **请求和保持**
          - **循环等待**
    - 死锁预防 -- **破坏四个必要条件之一**
       - **破坏互斥**
          - 互斥资源改造为允许共享使用
       - **破坏不可剥夺**
          - 请求新资源得不到满足，释放已有资源，以后需要时再重新申请
       - **破坏请求和保持条件**
          - 一次性申请完全部资源
          - 分配运行需要的部分资源，待全部释放后，再请求新的资源
       - **破坏循环等待条件**
          - 对各类资源编号，每个进程必须按照编号递增的顺序请求资源
    - 死锁避免
       - 基本概念
          - 安全序列：系统按照某种进程推进顺序，使每个进程都可顺利完成
          - 安全状态：能找到一个安全序列
          - 不安全状态：无法找到安全序列
          - 安全状态一定不会死锁，不安全状态可能死锁，发生死锁一定处于**不安全状态**
       - 银行家算法（常规选择计算）
          - 资源总量
          - 资源可利用数量
          - 资源最大需求数量
          - 资源已经分配数量：资源总量 - 已分配数量
          - 资源尚需分配数量：资源最大需求量 - 已分配数量
          - 通过将资源可利用数量与每个进程的资源尚需分配数量对比，求安全序列
            *进程执行完需归还已分配的资源数量，资源可利用数量会跟着变多*
    - 死锁的检测和解除
       - 死锁检测
          - 资源分配图的画法
          - 资源分配图的简化过程
          - 资源分配图简化后，还有边相连的进程就是死锁进程
       - 死锁解除
          - 资源剥夺法
             - 把部分死锁进程的资源剥夺并再分配
          - 撤销进程法
             - 终止进程并回收资源
          - 进程回退法
             - 将一个或多个死锁进程回退到之前的状态，需要系统保持进程的历史信息，设置还原点

# 生产者-消费者问题

##### 10.19

**六步解题法**：
 1. 有几类进程 -> 每类进程对应一个函数
 2. 在每个函数内，用中文描述进程**动作** -- 有些不断重复（加`while(1)`），有些只做一次
 3. 分析每个动作前是否需要 P 什么（取一个临界资源）？ -- ==有P必有V，先写P再写V==
     - P操作时，注意隐含的**互斥**操作（即对缓冲区的操作）
 4. 所有P、V操作写完之后，**再定义信号量**，==🟢最后**确定信号量的初值**==
 5. 检查如果**多个P操作连续**的地方，是否会导致死锁？
     - 如果发生死锁，尝试调整P操作的顺序
 6. 读题检查，是否满足题意

## 举例

引例：某工厂有**两个**生产车间和**一个**装配车间，两个生产车间分别生产A、B两种零件，装配车间的任务是把A、B两种零件组装成成品。两个生产车间每生产一个零件之后，都要分别把他们送到装配车间的货架F1、F2上。F1存放A，F2存放B，且F1、F2的容量**均为10件**。装配工人每次从货架上取一个零件A一个零件B后组装成产品。请使用P、V操作正确管理

**思考**：（六步解题法）
 1. 三类操作，即两个生产车间和一个装配车间
     - `生产1(){}`，`生产2(){}` , `装配(){}`
 2. 分析动作
     - 生产1：生产A零件，将A零件放入F1（while）
     - 生产2：生产B零件，将B零件放入F2（while）
     - 装配：从F1取一个A，从F2取一个B，组装A+B（while）
 3. 分析P、V：==颜色为先思考==，==🔵颜色为后思考==，==🟢颜色为信号量==
     - 生产1：
        - **生产A零件**
	    - ==需要P一个F1货架空闲位置empty1==
		    - ==🟢 P 互斥信号量mutex1==
            - **将A零件放入F1**
            - ==🟢 V 互斥信号量mutex1==
        - ==🔵为F1货架V一个零件A==
     - 生产2：
        - **生产B零件**
        - ==需要P一个F2货架空闲位置empty2==
            - ==🟢 P 互斥信号量mutex2==
	        - **将B零件放入F2**
	        - ==🟢 V 互斥信号量mutex2==
        - ==🔵为F2货架V一个零件B==
     - 装配：
        - ==需要从F1货架P一个零件A==
            - ==🟢 P 互斥信号量mutex1==
	        - **从F1取一个A**
	        - ==🟢 V 互斥信号量mutex1==
        - ==🔵取完A之后，需要V一个F1的空位==
        - ==需要从F2货架P一个零件B==
            - ==🟢 P 互斥信号量mutex2==
	        - **从F2取一个B**
	        - ==🟢 V 互斥信号量mutex2==
        - ==🔵取完B之后，需要V一个F2的空位==
        - **组装A+B**
     - 货架F1，F2为缓冲区，即需要对货架进行互斥访问
 4. 为信号量赋值，即：
     - F1的空位`empty1 = 10`
     - 对F1互斥访问的信号量`mutex1 = 1`
     - F1上的零件A的数量`A_num=0`
     - F2的空位`empty2 = 10`
     - 对F2互斥访问的信号量`mutex2 = 1`
     - F2上的零件B的数量`B_num=0`
 5. **检查死锁**，先P同步信号量，再P互斥信号量，这样就**不会发生死锁**
 6. 再次检查，最后转译成代码，抄上答题卡

# 读者-写者问题

##### 10.20

某男子足球俱乐部，有非常多教练、队员。每次足球训练开始前，教练、球员都需要先进入更衣室换衣服，俱乐部只有一个**更衣室**，且一次只能**一个教练**换衣服，但**队员可以一块换衣服**，更衣完成后，才可参加足球比赛
 1. 起初俱乐部规定：如果球员和俱乐部均要使用更衣室，则**教练优先**，使用PV操作描述上述过程的互斥与同步
 2. 后来，更改规定 -- 队员和教练遵循**先来先用**规定，公平使用更衣室，使用P、V操作描述上述过程

*==注：书中读者写者都是**读**优先，而（1）这里是**写**优先 ==*

读者写者的精髓，是一个**count**变量

（1）**分析**：
可以设置**两道门**，队员从read进入，教练从write进入，第一个教练到达时，可==将read，write上锁==，结束后将write解锁，如果是最后一个教练将read解锁

可用一个count记录有几个教练
```cpp
semophore readLock = 1;  //互斥信号量，给队员上锁
semophore writeLock = 1; //互斥信号量，给教练上锁
semophore rmutex = 1;    //互斥信号量，实现对readcount互斥访问
semophore wmutex = 1;    //互斥信号量，实现对writecount互斥访问
int readcount = 0,writecount = 0;

//队员进程
Reader(){
	while(true){
		P(readLock); //队员到达时对read上锁
		P(rmutex);
			readcount++;
			if(readcount == 1) P(writeLock);//第一个进入的队员对教练上锁
		V(rmutex);
		V(readLock);//每个读者正式更衣前对read解锁
		
		队员更衣;
		
		P(rmutex);
			readcount--
			if(readcount == 0) V(writeLock); //最后一个更衣的队员对教练解锁
		V(rmutex);
		
	}
}

//教练进程
Write(){
	while(true){
		P(wmutex);
			writecount++;
			if(writecount == 1) P(readLock);//第一个到达的教练对队员上锁
		V(wmutex);
		P(writeLock);//每个教练更衣前都要Pw，保证教练间互斥
		
		教练更衣;
		
		V(writeLock);
		P(wmutex);
			writecount--;
			if(writecount==0) V(readLock);//最后一个教练结束后，对队员解锁
		V(wmutex);
	}
}
```

（2）**分析**：==读写公平==
设置**一个锁**，新人到来时，先用一个队列将他们排序，队头**人员**尝试抢锁 
 - 若是队员，若更衣室内队员**不为零**，则直接进入
 - 若是教练，则阻塞

```cpp
semaphore lock = 1; //用于实现对更衣室的共享访问
int count = 0; //记录当前有几个队员在使用更衣室
semaphore metux = 1; //保证对count的互斥访问
semaphore queue = 1; //用于实现读写公平

//教练进程
writer(){
	while(true){
		P(queue); //排队
		P(lock);  //尝试上锁
		V(queue); //尝试唤醒下一个队头进程
		
		教练更衣;
		
		V(lock);  //
	}
}

//队员进程
reader(){
	while(true){
		P(queue);  //先排队
		P(mutex);  //互斥访问count
			if(count == 0)
				P(lock); //第一个到达的队员上锁
		count++;   //队员数+1
		V(mutex);
		V(queue);
		
		队员更衣;
		
		P(mutex);  //互斥访问count
		count--;   //队员数-1
			if(count == 0) //最后一个离开的队员应该解锁
				V(lock);
		V(mutex);	
		
	}
}
```

# 哲学家进餐

哲学家进餐问题关键点在于**限制并行**，主要是三种思路
 1. 限制申请资源的顺序（==解法1不通用，不建议使用==）
     - 比如、：规定只能奇数号取左边资源，偶数号取右边资源
 2. 限制并发进程数（==解法2通用，但并发度不高，不建议使用==）
     - 比如：规定同一时间只能有一个哲学家就餐（限制并行）
 3. 让进程一口气取得所有资源，再开始运行（==解法3很通用，且并发度高，建议使用==）
     - 比如：哲学家只有能够取得两个筷子的时候才会就餐

**考试技巧 -- 骗分模板**（<span style="color:red;font-weight:bold;">有风险，非必要不使用</span>）
 - 即使用int变量表示资源

流程：
 1. 定义一个**大锁**
 2. ==用int型变量定义资源数量==
     - 比如有a、b、c三种资源，分别有9、8、5个，则`int a=9,b=8,c=5;`
     - 以此为基础写代码
 3. 每个进程开始运行的时候，一口气拿下所有资源
    ```cpp
    while(1){
	    P(lock);
	    if(所有资源都够){
		    所有资源int值减少;
		    取xxx资源;//一口气拿走所有资源
		    V(lock);//拿完所有资源解锁
		    break;//跳出循环
	    }
	    V(lock); //资源不够，解锁，再循环尝试一次
    ```

## 举例

**引例**：一荤、一素、一汤、一米饭，是干饭人的标配。到饭点的时候，每个干饭人进入食堂，需要做：**拿一个盆打荤菜、拿一个盆打素菜、拿一个盆打汤，再拿一个盆打饭，然后找一个位置坐下吃饭，吃完饭将盆还给食堂**，现在食堂有==N个==盆，==M个==座位，使用PV操作描述上述同步与互斥

### 暴力解

**暴力骗分解如下**：
``` cpp
semaphore mutex = 1;//互斥信号量，保证所有进程对pt变量，seat变量的访问互斥
int pot = N;  //盆数N
int seat = M; //座位数M

Eatman(){
	进食堂;
	
	while(1){
		P(mutex); //资源上锁
		if(pot>=4 && seat>=1){ //所有资源都够
				pot -= 4;//一口气拿走所有
				seat -=1;
			V(mutex); //拿完资源，解锁
			break;
		}
		V(mutex); //资源不够，解锁
	}//while
	
	打荤菜;
	打素菜;
	打汤;
	打饭;
	吃饭;
	
	P(mutex); //资源上锁
	pot += 4; //一口气归还所有资源
	seat +=1;
	V(mutex); //资源解锁
	
	离开食堂;
}
```

### 传统解法

#### 限制并发

**思考**：若有5个哲学家，若限制只有4个人可以同时进餐，那么至少会有一个哲学家可以同时获得左右筷子，从而预防死锁

即在这个题中，每个干饭人只有拿到4个盆才能吃饭，则最坏情况就是==每个人持有3个盆，同时在等待第4个盆==，此时若再多一个盆，就可以解决死锁，所以设置同时**抢盆的人数为x**，只需满足$3x+1\leq N$，则**一定不会死锁**
```cpp
semaphore pot = N;//同步信号量，用于表示盆
semaphore seat = M;//同步信号量，表示座位
semaphore x = (N-1)/3;//同步信号量，表示最多允许多少人吃饭

eatMan(){
	P(x); //进食堂拿盆之前，查看是否已经达到上限
	
	进食堂;
	
	P(pot);//拿一个盆
	打荤菜;
	
	P(pot);//拿一个盆
	打素菜;
	
	P(pot);//拿一个盆
	打汤;
	
	P(pot);//拿一个盆
	打饭;
	
	P(seat);//占座
	吃饭;
	V(seat);//让座
	V(pot);//还盆
	V(pot);//还盆
	V(pot);//还盆
	V(pot);//还盆
	V(x);
	
	离开食堂;
}
```

#### 最通用解 -- 取所有资源

**思考**：采用静态分配的思想，让进程一口气取得所有资源，再开始运行

```cpp
semaphore mutex = 1;//互斥信号量，保证所有进程对pot，seat的互斥访问
semaphore pot = N;//同步信号量，表示盆
semaphore seat = M;//同步信号量，表示座位

//干饭人进程
EatMan(){
	进食堂;
	
	P(mutex);
	P(pot);
	P(pot);
	P(pot);
	P(pot);//一口气拿4个盆，并占座
	P(seat);
	V(mutex);
	
	打荤菜;
	打素菜;
	打汤;
	打饭;
	
	V(seat);//让座
	V(pot);//还盆
	V(pot);//还盆
	V(pot);//还盆
	V(pot);//还盆

	离开食堂;
}
```

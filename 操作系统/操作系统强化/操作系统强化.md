# 第二章 进程与线程
[[第二章 进程与线程Q]]

**思维导图**
 - 进程与线程
    - 进程与线程的基本概念
        - 进程
           - 包含程序段、数据段、进程控制块PCB
           - 资源分配的基本单位
        - 线程
           - 独立调度的基本单位，可访问其隶属进程的资源
           - 线程控制块TCB
    - <span style="color:red;font-weight:bold">进程的状态与转换</span>
       - 就绪态->运行态：就绪的进程被调度，**获得CPU资源**
       - 运行态->就绪态：时间片用完或者被**更高优先级**的进程抢占
       - 运行态->阻塞态：需要的资源**无法申请**时或者**IO操作**开始
       - 阻塞态->就绪态：**IO操作完成**
       - 线程的状态与转换过程和上述基本相同
    - *进程控制：进程的创建、进程的终止、进程的阻塞和唤醒*
      *线程的组织与控制：线程控制块、线程的创建、线程的终止*
    - 进程间通信
       - 共享内存
       - 消息传递
       - 管道
       - 信号
    - 线程的实现级方式
       - 用户级线程
          - 用户视角能看到的线程
          - 线程管理（创建、撤销、切换）由应用程序在**用户态**完成，无需操作系统干预
       - 内核级线程：线程的所有工作在内核空间内（内核态）实现
 - CPU调度
    - 调度的基本概念：从就绪队列，按照某种规则选择一个进程并将CPU分配给该进程运行
    - 调度的实现
        - *调度程序*：未考过
        - *调度的时机、切换与过程*
        - 进程调度的方式
           - 非抢占调度方式
           - 抢占调度方式
        - **闲逛进程**：闲逛进程不需要CPU之外的资源，它不会被阻塞，**优先级最低**
           - 目的是让CPU持续工作，防止空闲
           - 没有就绪进程，则调度闲逛进程；只要有其他进程就绪，就立即让出CPU
    - 调度的目标，常见评价指标
      *常考计算题，较简单需画甘特图分析* 
        - CPU利用率：$\dfrac{CPU有效工作时间}{总时间}$
        - 周转时间：完成时间 - 提交时间
        - 平均周转时间
        - 带权周转时间：$\dfrac{周转时间}{运行时间}$
        - 平均带权周转时间
        - 等待时间：进程等待CPU的时间之和
        - 响应时间：从用户提交请求到系统首次产生响应（即首次执行）所用的时间
    - *进程切换*：上下文及其切换机制 
    - <span style="color:red;font-weight:bold">CPU调度算法</span>
      重点掌握、需结合书上概念以及真题学习
        - 先来先服务调度算法
        - 短作业优先调度算法
        - 高响应比优先调度算法
           - $响应比=\dfrac{等待时间+执行时间}{执行时间}$
        - 优先级调度算法
           - 静态优先级
           - 动态优先级
           - 进程优先级设置依据
              - 系统进程 > 用户进程
              - 交互性进程 > 非交互性进程
              - IO进程 > 计算型进程
        - 时间片轮转调度算法
        - 多队列调度算法
        - 多级反馈调度算法
           - 不同队列的优先级不同，第1级最高
           - 各个队列时间片大小各不相同，优先级越高的队列，时间片越小
           - 进程未执行完时依次被降级到下一级队列
           - 前面所有队列进程为空时，才会调度后续队列
        - ==书表格2.4，常见进程调度算法的特点对比==
    - 多处理器调度（大纲有，未考过）
 - <span style="color:red;font-weight:bold">同步与互斥</span>
    - 同步与互斥的基本概念
        - **临界资源**
           - 一次仅允许一个进程使用的资源称为临界资源
           - 临界区：访问临界资源的代码称为临界区，临界需互斥访问
        - **同步**
           - 进程之间按照想要的顺序执行，==区别于异步（以不可预知的顺序推进）==
        - **互斥**：不能同时发生
        - **实现临界区互斥需要遵循的准则**
            - 空闲让进
            - 忙则等待
            - 有限等待
            - 让权等待（==非必须遵循==）
               - 记录型信号量可以实现让权等待，P操作中有block语句
               - 软件实现互斥的4种方法
               - 硬件实现互斥的3种方法
               - 整型信号量，均不能实现让权等待
    - 互斥的基本实现方法
      结合代码理解，代码难度不高，理解为主
        - **软件方法**
           - 单标志法
              - 两个进程必须交替进入临界区，有可能未被**空闲让进**
           - 双标志先检查法
              - 无需交替进入，但可能同时进入临界区，可能违背**忙则等待**
              - 先while循环检查对方标志位，再修改自己标志位
           - 双标志后检查法
              - 可能都进不了临界区，可能违背**空闲让进和有限等待**
              - 先修改自己的标志位，再while循环检查对方标志位
           - 皮特森算法
              - 结合单标志法和双标志后检查法，遵循空闲让进，忙则等待，有限等待，未遵循让权等待
        - **硬件方法**
           - 中断屏蔽方法：关中断限制了并发能力，不适用于多处理器系统
           - TestAndSet指令（简称TS指令）
           - Swap指令
           - TS指令和Swap指令思想类似，并通过一个共享变量lock
            进入临界区检查lock的值，并且修改lock的值为true
            若修改之前lock为false，则进入临界区
            若修改之前lock为true，则执行循环忙等
            进程退出临界区时，将lock修改为false 
    - 信号量
        - 整型信号量
          结合wait和signal代码理解
            - 信号量是整数，只是用来反映资源的数量
            - 未遵循让权等待
        - 记录型信号量
          结合wait和signaldiamond理解
            - 记录型信号量是一个单独的结构体类型：内部含有信号量的值以及因为该信号量阻塞的进程链表
            - 数值含义：记录型信号量有数值，并且有含义，整数代表可用的资源数量，负数代表阻塞的进程数量
            - wait：数值减1，随后如果<0，则阻塞进程，故可以实现让权等待
            - signal：数值加1，随后如果<=0，则唤醒对应进程
            - <span style="color:red;font-weight:bold">记录型信号量的应用</span>（以下是整个PV大题的基础，PV操作大题的本质是分析实现同步互斥的关系）
                - 利用信号量实现进程互斥
                - 利用信号量实现进程同步
                - 利用信号量实现前驱关系：本质就是同步
        - 让权等待（非必须遵循）
          记录型信号量**可以实现**让权等待，P操作中有block语句
          软件实现互斥的四种方法，硬件实现互斥的三种方法，以及整型信号量均**不能**实现让权等待
    - <span style="color:red;font-weight:bold">经典同步问题</span>
      需熟练掌握代码，**关注信号量的个数、含义作用、初始值、位置**
      **理解P和V的阻塞和唤醒流程**
        - **生产者消费者问题**
        - **哲学家进餐问题**
        - **读者写者问题**
    - 锁
    - 条件变量
       - 区别于记录型信号量
       - 条件变量的wait/signal操作类似于信号量的P/V操作，可以实现进程的阻塞/唤醒
       - 条件变量是**没有数值**的
          - 记录型信号量**有数值**，并且数值有含义，整数代表可用的资源数量，负数代表阻塞的进程数量
 - <span style="color:red;font-weight:bold">死锁</span>
    - 死锁的基本概念
       - 多个进程因竞争资源而造成的一种僵局（互相等待对方手里的资源），使得各个进程都被阻塞，各个进程均无法向前推进
       - <span style="color:red;font-weight:bold">死锁的四个必要条件</span>
          - **互斥**
          - **不可剥夺**
          - **请求和保持**
          - **循环等待**
    - 死锁预防 -- **破坏四个必要条件之一**
       - **破坏互斥**
          - 互斥资源改造为允许共享使用
       - **破坏不可剥夺**
          - 请求新资源得不到满足，释放已有资源，以后需要时再重新申请
       - **破坏请求和保持条件**
          - 一次性申请完全部资源
          - 分配运行需要的部分资源，待全部释放后，再请求新的资源
       - **破坏循环等待条件**
          - 对各类资源编号，每个进程必须按照编号递增的顺序请求资源
    - 死锁避免
       - 基本概念
          - 安全序列：系统按照某种进程推进顺序，使每个进程都可顺利完成
          - 安全状态：能找到一个安全序列
          - 不安全状态：无法找到安全序列
          - 安全状态一定不会死锁，不安全状态可能死锁，发生死锁一定处于**不安全状态**
       - 银行家算法（常规选择计算）
          - 资源总量
          - 资源可利用数量
          - 资源最大需求数量
          - 资源已经分配数量：资源总量 - 已分配数量
          - 资源尚需分配数量：资源最大需求量 - 已分配数量
          - 通过将资源可利用数量与每个进程的资源尚需分配数量对比，求安全序列
            *进程执行完需归还已分配的资源数量，资源可利用数量会跟着变多*
    - 死锁的检测和解除
       - 死锁检测
          - 资源分配图的画法
          - 资源分配图的简化过程
          - 资源分配图简化后，还有边相连的进程就是死锁进程
       - 死锁解除
          - 资源剥夺法
             - 把部分死锁进程的资源剥夺并再分配
          - 撤销进程法
             - 终止进程并回收资源
          - 进程回退法
             - 将一个或多个死锁进程回退到之前的状态，需要系统保持进程的历史信息，设置还原点

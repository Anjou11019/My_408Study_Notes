# 网络应用模型

##### 7.16

## 客户服务器C/S模型

在客户/服务器（Client/Server）模型中，存在一个始终处于开启状态的主机，称为**服务器**，它负责响应多个称为**用户**的主机的请求

**工作流程**：
 1. 服务器长期运行，等待客户发来请求
 2. 客户**主动**向服务器发出**服务请求**，可见1，客户必须提前知道服务器的地址（IP:端口）
 3. 服务器**被动**处理客户请求，并将处理结果返回给客户，可见服务器不需要提前知道客户端的地址

**C/S模型特点**：
 - 客户、服务器地位不平等，服务器位于中心
 - 客户进程之间不直接通信

**优点**：
 - 便于集中管理（数据资源、带宽资源等）

**缺点**：
 - 如果服务器损坏，影响全局
 - ==处于中心位置的服务器**负载大**，服务器性能决定了整个系统的性能==


## P2P模型

Peer-to-Peer，任意两台主机之间成为**对等方**

**特点**：
- 去中心化，主机之间地位平等
- 主机之间直接通信

**优点**：
 - 单个节点损坏不影响全局
 - 个节点分摊负载

**缺点**：
 - 一个主机被服务的同时，也在为其他主机服务，主机负载大
 - 可能导致网络数据流量大，网络拥塞

# 域名系统DNS

**域名系统DNS**（Domain Name System）：是互联网使用的命名系统，将便于人们记忆、具有特定含义的主机名转换为便于机器处理的IP地址
 - 采用C/S模型，运行在**UDP上，通常端口号为53**
 - DNS是**应用层协议**
 - DNS是**分布式系统**
 - 分为三个部分：
    - **层次域名空间**
    - **域名服务器**
    - **解析器**

**分布式系统**（Distributed System）
 - 数据和服务分散在多台服务器上，协同工作完成任务（去中心化）
**集中式系统**（Centralized System）
 - 所有数据和服务集中在一台或少数几台服务器上进行处理（中心化）

## 层次域名空间

##### 7.17

域名书写规则：
 - 低级域名在左，高级域名在右
 - 域名由**标号Lable**组成，标点之间用.分隔
 - **标号**:主要由英文、数字组成，允许使用-
 - 单标号 $\leq$ 63字符，全域名总长 $\leq$ 255字符

*DNS对域名的级数没有专门的上限*
 - 顶级域名由ICANN统一管理

**域名、域的定义**
 - *顶级域名之上还有一个根域名，被记作一个点，但一般不写*
 - **域名**（Domain Name）：主机或路由器的层次结构名称
 - **域**（Domain）：名字空间中可被管理的划分

**顶级域名TLD分类**（Top Level Domain）
 - 国家顶级域名ccTLD（country-code）
 - 通用顶级域名gTLD（generic）
    - .com：公司
    - .net：网络服务
    - .org：非营利组织
 - 基础结构域名
    - 只有一个，用于**反向域名解析**（.arpa）

## 域名服务器&域名解析过程

### 域名服务器

**四类域名服务器**
 - 根域名服务器
    - 记录并维护**所有**==顶级域名服务器==的IP地址
 - 顶级域名服务器
    - 记录并维护自身域下**所有**==权限域名服务器==的IP地址
 - 权限域名服务器
    - 记录并维护自身域下**所有（或部分）**==主机==的【域名 -> IP】信息
 - 本地域名服务器
    - ISP通常在各个地区部署本地域名服务器，为用户就近提供DNS解析服务
    - **本地域名服务器**是用户侧默认的DNS入口，通常由DHCP在主机入网时自动配置本地域名服务器IP地址
    - **本地域名服务器**采用**DNS缓存**提升域名的重复查询效率，DNS缓存记录会设置*生存时间TTL*，到期失效
    - 用户主机的**解析器**也会保存本地DNS缓存

**特点**：
 - 通过 根->顶级 -> 权限域名服务器 逐级查询，一定可以查到任意域名对应的主机IP地址
 - 全世界**有13组**==根域名服务器==，每组至少绑定一个**固定IP地址**
 - *每组域名服务器并非单一主机，而是全球多地部署的大量镜像节点，支持“anycast**任播**”，可就近访问、冗余容灾*

通常而言，操作系统设有系统级DNS解析器(resolver)，供上层应用程序调用
 - 浏览器这种高频DNS应用也会自己实现应用级DNS解析器

### 域名解析过程

**域名解析**：将域名转换为IP地址的过程
 - 递归查询
 - 迭代查询

# FTP文件传输协议

##### 7.20

**FTP的功能**：
 1. 提供**不同种类主机系统之间**的文件传输能力（软、硬件体系都可以不同）
 2. 以**用户管理权限**的方式提供用户对远程FTP服务器上的文件管理能力
 3. 以**匿名FTP**的方式提供==公用文件共享==的能力

## FTP工作原理、控制连接和数据连接

FTP是**应用层**协议，采用**C/S模型**，基于**TCP**的可靠传输

**服务器端**（主进程，只有一个）：
 - 从属进程（多个），每个已登录用户都对应1个控制进程+0个或1个数据传输进程

**控制连接**（控制进程）：**持久**连接，整个FTP会话期间，都保持该TCP不中断

**数据连接**（数据传送进程）：**非持久连接**，每次文件传输前建立连接，结束后就关闭连接

**FTP的工作原理**：
 - **登录**阶段：
    1. ==服务器端==主进程监听**TCP21**端口（固定）
    2. ==客户端==控制进程（分配随机端口，比如8888）向==服务器==**21端口**发送TCP连接请求
    3. ==服务器==主进程同意建立TCP连接，并创建一个控制进程，由控制进程**继承**这个TCP连接（控制连接建立完成）
    4. C->S（控制连接）：==客户端==通过控制连接发出FTP登录请求
    5. S->C（控制连接）：==服务器端==控制进程通过控制连接返回登录成功/失败响应
- **数据传送**：主动/被动模式
   - 主动模式**PORT**：==服务器==数据传送进程**主动**向==客户端==数据传送进程发起数据连接（==考研若不强调，默认主动模式==）
      1. C->S（控制连接）：指明接下来这次传输采用**主动模式PORT**，==客户端==IP+随机端口
      2. S->C（控制连接）：返回对1的响应
      3. C->S（控制连接）：下载文件《/C/D》
      4. S->C（控制连接）：==服务器==检查当前用户是否有权下载指定文件，再返回对3的响应
      5. S->C（建立数据连接）：==服务器==数据传输进程用**20端口（固定）** 主动与==客户端==建立TCP数据连接
      6. S->C（数据连接）：正式开始传输文件《/C/D》
      7. S->C（断开数据连接）：文件数据传输完成后，==服务器==主动断开TCP连接（4次挥手）
   - 被动模式**PASV**：==服务器==数据传送进程**被动等待**客户端数据传送进程发起数据连接
      1. C->S（控制连接）：指明接下来这次传输采用**被动模式PASV**
      2. S->C（控制连接）：==服务器==返回对1的响应，告知对方本次传输的**随机端口（比如2111）** 
      3. C->S（控制连接）：上传==客户端==文件到==服务器==的《/C》目录
      4. S->C（控制连接）：==服务器==检查当前用户是否有权上传，再返回对3的响应
      5. C->S（建立数据连接）：==客户端==分配一个**随机端口（比如1234）** 与==服务器==建立TCP数据连接
      6. C->S（数据连接）：正式开始上传文件到==服务器==的《/C》目录
      7. C->S（断开数据连接）：文件数据传输完成后，==客户端==主动断开TCP连接（4次挥手）
  - **登出**阶段：
      1. C->S（控制连接）：==客户端==通过控制连接向==服务器==发送**登出QUIT**命令
      2. S->C（控制连接）：==服务器==返回对1的响应
      3. 经过TCP四次挥手（==服务器==发第一次挥手），断开控制连接，FTP会话结束
   - *注：数据传送之前，客户端必须发送PORT/PASV命令来制定模式*

## FTP的特点

**FTP的特点**：
 - FTP**文件修改效率低**（需要整体下载再上传）
 - FTP分离控制与数据，可称控制信息是**带外传输**的（优点是控制命令不会因为数据传输而阻塞）
 - ==客户端==可通过控制连接**请求服务器返回文件列表LIST**，==服务器==传输文件列表信息是通过**数据连接**进行的
 - 对于数据传送，RFC官方默认==主动模式==，由于主动模式无法**穿透NAT**，后来在实践中更多的默认采用==被动模式==

# 电子邮件

**术语**：
 - **SMTP**（Simple Mail Transfer Protocol）：简单邮件传输协议 -- 用于实现**发送邮件**
 - **POP3**（Post Office Protocol v3）：邮局协议 -- 用于实现**接收邮件**
 - **MIME**（Multipurpose Internet Mail Extensions）：多用途因特网邮件拓展 -- 并非协议，只是**格式规范**（描述邮件长什么样，如何编码）

## 电子邮件系统的组成结构

**三大组成结构**：
 1. **用户代理**
     - 提供用户界面，编辑、发送、接收文件
 2. **邮件服务器**
     - 存放用户邮件，发送/接收邮件，扮演SMTP客户端&服务器**双重角色**
 3. **电子邮件协议**

**SMTP**：用于发邮件（HTTP和HTTPS都可以发邮件），基于TCP，服务器端用**25端口**

**POP3**（现在还有一个IMAP协议，这个更能满足现在人的需求）：用于接收文件，基于TCP，服务器端使用**110端口**

## 电子邮件格式

邮件 = **信封** + **内容**
 - **内容** = ==首部== + 主体
    - 首部：To、From、Subject三个字段组成，To/From是必填，Subject选填
    - **信封**是给SMTP协议使用的数据结构（==谁发的、发给谁==），由用户代理根据首部自动生成

**SMTP的局限性**：
 - 1980s 规定==SMTP只能传输7-bit ASCII码==，由此邮件内容仅支持纯英文邮件，不支持发送中文、更不可能支持发文件

**MIME**不是协议，只是**格式规范**
 1. 定义了5个新的邮件首部字段
 2. 定义了许多邮件主体的格式（图片、文本等）
 3. 定义了传送编码（比如Base64）
     - Base64类似于64进制，每6bit二进制映射为一个ASCII字符

## SMTP&POP3

SMTP发出的每条命令（Command），都会有服务器回应（Reply）
 - HELO：相当于打招呼
 - MAIL FROM：指明==“谁发的”==
 - RCPT TO：指明==“发给谁”==，服务器会检查收件人是否存在，并给出回应
 - DATA：相当于告诉服务器==“接下来要开始发送邮件内容了”==
 - QUIT：相当于告诉服务器==“邮件发完了”==

SMTP为==推PUSH==通信方式，可用于
 - 发送方用户代理 -> 发送方邮件服务器
 - 发送方邮件服务器 -> 接收方邮件服务器

**POP3**为==拉PULL==通信方式，只能用于:
 - 接收方邮件服务器 -> 接收方用户代理
 - POP3下载邮件时，可以选择**下载并删除**或者**下载并保留**

# WWW万维网

网页 = ==1个==HTML文件 + ==n个==网页元素

浏览器访问一个网页的过程：
 1. 用户输入网址
 2. 浏览器通过DNS服务器查询域名对应的IP地址
     - 浏览器会将查询结果 域名->IP 缓存到本地
 3. 浏览器与<Web服务器IP地址:80端口>建立TCP连接
 4. 浏览器在握手3中携带HTTP请求报文
     - 指明要访问哪个html网页
 5. 服务器返回HTTP响应报文
     - 携带html文件
 6. 如果html引用了其他==n个元素==，还需要==n组==HTTP请求&响应
     - **持续**、**非持续**工作方式有所区别
        - 非持续：==每请求一个文件，至少需要2倍RTT时间==
           - **特点**：每建立一次TCP连接，仅完成一组HTTP请求&响应
           - 可以通过**并行TCP连接**加快获取==n个==网页元素的速度
        - 持续
           - **特点**：每建立一次TCP连接，可以完成多组HTTP请求&响应
           - **分类**：
            - 流水线
                - 可以连续发出多个HTTP请求
            - 非流水线
               - 只有上一次HTTP请求收到响应后，才能发出下一次HTTP请求

HTTP**请求**报文通常很小，因此不考虑TCP报文段传输时延
HTTP**响应**报文通常很大，因此通常要考虑TCP报文段传输时延

## 万维网的组成

**WWW万维网**，World Wide Web
 - 统一资源定位符URL
    - URL = <协议>://<主机>:<端口>/<路径>  --指向万维网上的某个特定资源
    - 端口可以省去，因为有默认值
 - 超文本传输协议HTTP
    - **应用层**，基于TCP
 - 超文本标记语言HTML
    - 一种文档结构的标记语言，使用一些约定的标记对页面上的信息、格式进行描述

## HTTP

HTTP是一种**面向事务**的==应用层协议==
 - 请求报文
    - GET：请求读取由URL标识的信息
    - HEAD：请求读取由URL标识的信息的首部
    - POST：给服务器添加信息
    - CONNECT：用于代理服务器
 - 响应报文
    - 1xx：信息
    - 2xx：请求成功
    - 3xx：重定向
    - 4xx：客户端错误
    - 5xx：服务器错误

Cookie：
 1. ==客户端==HTTP请求：登录个人账号
 2. ==服务器==生成Cookie识别码，并存储在服务器，相当于临时身份证
 3. ==服务器==HTTP响应：携带Cookie字段
 4. ==客户端==将Cookie缓存在本地
 5. 后续HTTP请求（携带Cookie）

HTTP/1.0 默认使用==非持续连接==
HTTP/1.1 默认使用==持续连接==

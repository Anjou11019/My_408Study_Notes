# DNS
##### 11.4

采用C/S模型，运行在**UDP上，通常端口号为53

**特点**：
 - 通过 根->顶级 -> 权限域名服务器 逐级查询，一定可以查到任意域名对应的主机IP地址
 - 全世界**有13组**==根域名服务器==，每组至少绑定一个**固定IP地址**
 - *每组域名服务器并非单一主机，而是全球多地部署的大量镜像节点，支持“anycast**任播**”，可就近访问、冗余容灾*

通常而言，操作系统设有系统级DNS解析器(resolver)，供上层应用程序调用
 - 浏览器这种高频DNS应用也会自己实现应用级DNS解析器

**域名解析**：将域名转换为IP地址的过程
 - 递归查询
 - 迭代查询

DNS封装到**UDP报**文中，一起封装到**IP数据报**中，最后一起封装进**MAC帧**中

### 并行TCP

![[图1并行TCP非持续连接HTTP.png]]

依旧==每一个TCP连接，只能发出一个HTTP请求==

## 持续连接

### 流水线

![[图2持续连接，流水线HTTP请求.png]]

在一个TCP连接建立后，后续可持续对该TCP连接进行利用，==连发多个请求，收到多个响应==
 - 即握手3 -> 响应 -> 请求1，请求2，请求3 -> 响应1，响应2，响应3 -> 释放连接

### 非流水线

![[图2持续连接，非流水线HTTP请求.png]]

在一个TCP连接建立后，后续可持续对该TCP连接进行利用，**一个请求对应一个响应**
 - 即握手三 -> 响应 -> 请求 -> 响应 -> 请求 -> 响应 -> 释放

# FTP文件传输协议

FTP是**应用层**协议，采用**C/S模型**，基于**TCP**的可靠传输

FTP**控制端口 端口号：20**，**数据传送进程 端口号：21**

控制连接和数据连接是**并行**的TCP连接

## 一次Web访问中的逐层协议封装

UDP数据报使用16bit表示UDP长度，即UDP长度**理论最大值** = 65535B

但当UDP数据报放入IP数据报的数据部分时，可放入的**最大长度** = 65515B
 - 因为IP数据报也使用16bit表示IP数据报长度，数据部分需要减去20B最小首部长度

HTTP被TCP数据报分片后，除第一个分片之后的每个小片**不用**增加独立首部，因为TCP天然的带有**序号**字段，可以保证HTTP按序到达

**条件**：
 1. 以太网**MTU = 1500B**
 2. IP首部**20B**，TCP首部**20B**，UDP首部**8B**
 3. 设TCP连接的**MSS = 1460B**

主机H0连接在以太网上，通过默认网关访问www.dlidli.com，**问题**：
 1. **DNS查询**：==🟣H0发出的DNS查询报文为**40B**，求该查询在UDP首部的**长度字段值**、IP分组的**总长度**、以太网**帧长**？==
     -  **DNS封装过程**：
	   1. 应用层：| DNS报文 **40B** |
       2. 传输层：| UDP首部 **8B** | DNS报文 **40B** |，==共48B==
	   3. 网络层：| IP首部 **20B** | UDP首部 8B | DNS报文 40B |，==共68B==
	   4. 链路层：| 接收6B 发送6B 协议2B | IP首 + UDP首 + DNS报文 | 校验4B | ，==共86B==
 2. **TCP建立连接**：==🟣H0向Web服务器发出的**SYN报文段（TCP握手1）不携带数据，仅包含TCP首部**，求该报文段对应的IP分组总长度与以太网帧长？==
     - **握手1的TCP**：
       1. 传输层：| TCP首部 20B |，==共20B==
       2. 网络层：| IP首部 20B | TCP首部 20B |，==共40B==
       3. 链路层：| 6B 6B 2B | IP首+TCP首 40B + **6B填充** | 4B |，==共64B==
     - ==以太网帧的数据部分**最小为46B**== 
 3. **HTTP请求GET方法**：==🟣H0发出的HTTP GET请求报文共**200B**（**请求行+首部行+空行**，实体主体为空），求TCP报文段的长度、IP分组总长度、帧长？==
     - **请求报文封装**：
        1. 应用层：| HTTP报文 200B |
        2. 传输层：| TCP首部 20B | HTTP报文 200B |，==共计220B==
        3. 网络层：| IP首部 20B | TCP首部 20B | HTTP报文 200B |，==共计240B==
        4. 链路层：| 6B 6B 2B | IP首 + TCP首 + HTTP报文 240B | 4B |，==共计258B==
 4. **HTTP请求POST方法**：==🟣H0通过表单向Web服务器上传一张图片，POST的**请求行+首部行+空行**共**200B**，图片实体主体**3000B**，H0的TCP按协商得到的MSS分段发送，问：共分成几个TCP报文段？每个段的IP分组总长度和以太网帧长分别是多少？是否会发生IP分片？==
     - **HTTP请求报文**： MSS = 1460B
		1. 应用层：| HTTP请求 200+3000 = 3200B |
		2. 传输层：| TCP首 20B | 1460B | + | TCP首 20B | 1460B | +| TCP首 20B | 280B | 
		    - TCP首部的seq**不一定**非得从0开始，若握手1设置seq = 500，则
		       - 报文1的seq = 501，报文2的seq = 1961，报文3的seq = 3421
		    - 服务器对于握手3的ACK返回为 1961，即它所期待收到的序号
		3. 网络层：| IP首 20B | 1480B | + | IP首 20B | 1480B | +| IP首 20B | 300B |
		4. 链路层：| 662 | 1500B | 4B | + | 662 | 1500B | 4B | + | 662 | 320B | 4B |
 5. **同样的3200B应用层报文**，**若H0改用UDP发送**（设一次性交付3200B给UDP）：问：==🟣UDP长度字段是多少？在该以太网上会被分成几个IP分片？写出每个分片的**总长度、片偏移、MF标志**与对应帧长==
 6. 对比4，5问，思考==🟣**为什么用TCP时没有发生IP分片，而使用UDP时发生分片**==
     - **TCP**
     - **UDP**
     - *拓展：TCP的MSS是如何确认的？*
        1. **含义**：MSS指的是TCP报文段中**数据部分**的最大字节数，**不含TCP首部**
        2. **时机与方式**：在两个**SYN报文段（握手1、2）** 中，用**MSS选项通告对端**，含义是“发给我的段不要超过这么大”，因此两个方向的**MSS可能不同，发送方按对端通告的值分段**
        3. MSS通常由本端出接口的链路层MTU反推，例如：MSS = MTU - IP首部 - TCP首部 = 1500 - 20 - 20 = **1460B**，MSS默认值：若对端SYN报文段中未携带MSS选项，则按照**MSS = 536B**发送（IPv4标准建议的安全值）

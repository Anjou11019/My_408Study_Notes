已知：

 2. DHCP服务器：IP = 166.1.0.9/17，MAC = AA:BB:CC:DD:EE:09
 3. 默认网关：166.1.0.5
 4. 已占用地址：H1 = 166.1.0.1，H2 = 166.1.4.2
 5. 服务器决定向H0分配166.1.0.10

**新主机接入网络**：DHCP过程，以应届生求职为例
 1. 发现报文
     - 海投简历
     - **广播**
 2. 提供报文
     - 决定录用（OFFER），公司分配一个岗位
     - 包含：租期、默认网关IP、子网掩码、默认DNS IP
     - **一对一单播**
 3. 请求报文
     - **确认**OFFER，让其他公司知晓，已有OFFER（因为局域网内可能有多个DHCP）
     - 若此时有其他DHCP服务器之前分配过IP地址，在收到此报文后，会解冻分配的IP地址，并将其分给其他人
     - **广播**
 4. 回复报文
     - 签工作合同
     - **一对一单播**

| 阶段  | 链路层收          | 网络层收          | 传输层收 |

# 局域网内两台主机相互发送数据

![[图2局域网内主机交换信息.png]]

假设H0要往H2发生信息
 - H0：166.1.0.10，...EE:00
 - H2：166.1.4.2，...EE:02

ARP协议的工作范围是**本网络**

H0->H2
 1. 判断目的IP是否在同一网络
     - 子网掩码逐位AND，取IP高17位，若不同则发给**默认网关**；若相同则通过ARP协议找到目的MAC，将IP分组打包成单播帧然后发送
 2. ARP -> IP到MAC的映射
     - ARP过程
        1. 查本机的ARP表（ARP缓存）
        2. H0构造一个**ARP请求分组**
            - 将请求分组封装成MAC**广播帧**，目的MAC：FF:...:FF
            - 内部包含：我是谁（166.1.0.10；...EE:00）？我找谁（166.1.4.2，MAC？）？
        3. H1、H2、B3、DHCP均收到广播帧，只有H2更新ARP表，并构造**ARP响应分组**
            - 响应分组针对H0的**单播帧**，包含：我是谁（166.1.4.2，...EE:01）？
        4. 单播帧经过交换机，送达H0，此时交换表进行更新（H2 -> 对应的接口）
        5. H0更新ARP表
 3. H0单播帧发送IP分组

# 局域网外两台主机发送数据


![[图3局域网外主机交换信息.png]]

DliDli所属**局域网**如下：
![[图3DliDli所属局域网.png]]

假设H0 -> DliDli服务器发送数据
 - DliDli：
    - IP地址：200.1.1.4；
    - Web服务器端口号：80；
    - MAC：...:EE:D1

H0 -> DliDli
 1. H0判断目的IP与自身是否在同一网络？
     - 将200.1.1.4的高17位逐位AND
     - 否，发给默认网关，（DHCP后即可知道默认网关的IP地址了）
 2. 通过ARP找166.0.1.5的MAC地址
     1. 查ARP表
     2. 发ARP广播请求，查166.1.0.5的MAC地址
     3. 默认网关回复ARP单播响应，回复H0（IP：166.1.0.5，MAC：...EE:B3）
         - 默认网关也会更新它的ARP表
         - *注意：路由器有很多接口，但每个接口有**独立的**ARP表*
      - 交换机的交换表也会更新
 3. 给默认网关B3发送IP分组（目的DliDli服务器）
     - 此时IP分组
        - 源IP：166.1.0.10
        - 目的IP：200.1.1.4
     - MAC帧
        - 源MAC：..EE:00
        - 目的MAC：...:EE:B3
 4. 通过目的IP地址查路由表，由最长匹配原则得出从**B0转发**
 5. IP分组抵达200.1.1.1/24的路由器，通过查路由器的路由表得出需要从**C2接口**转发（假设C2 MAC = ...:EE:C2）
     - 假设C2的ARP表为空
        - C2包装ARP**广播**请求，找IP地址为200.1.1.4的MAC
        - DliDli收到后，包装ARP**单播**响应，回复C2（IP：200.1.1.4，MAC：...:EE:D1）
           - DliDli也会更新自己的ARP表
 6. IP分组经过C2接口，通过交换机转发交给DliDli服务器
     - 此时源MAC：...EE:C2
     - 目的MAC：...EE:D1

DliDli给H0回复一个分组（源IP：200.1.1.4/24，目的IP：166.1.0.10）
 1. 确认目的IP地址与自身是否在同一网络
     - 高24位逐位与AND 
	 - 否，发给默认网关
 2. 查ARP，确认默认网关的MAC地址（...EE:C2）
 3. 将IP分组封装成帧（源MAC：...EE:D1，目的MAC：...EE:C2）
 4. 交换机精准转发，发送到C2
 5. C2拆分帧，得出目的IP：166.0.1.10，通过查路由表，得知需从**C0**转发
 6. 路由器拿到目的IP地址，通过查路由表得知需从**B3接口**转发
 7. B3通过高17位逐位与得知目的地址在同一网络，通过查ARP表，得知H0的MAC地址
 8. B3将IP数据报封装成帧（源MAC：...:EE:B3，目的MAC：...:EE:00），转发给交换机
 9. 交换机通过查**交换表**，精准转发给H0
